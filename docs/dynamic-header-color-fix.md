# 动态配色 Header 修复

## 问题与已确认原因

用户反馈「简/繁」文字与旁边语音、收起键的配色不同，左侧快捷面板按钮在部分主题下出现独立背景色块。

在隔离包、合成空输入框与当前系统色板下，确认了两条独立原因：

- 「简/繁」继承原生功能键文字颜色，颜色本身参与动态配色，但文字未使用原生 Header 图标的透明度。深色无边框时，文字实心像素为 `#e4e4f0`，语音图标为 `#8e8e97`，与 `IconAlpha=153` 的混合结果对应。
- 原生 `style_sheet_color_rules_border.binarypb` 将 `.keyboard-header-area` 背景绑定到 `color_base`。生成器却在有无边框时都把 `color_access_points_menu_background` 映射为 `surface`。深色有边框时，Header 为 `#181920`，按钮背景为 `#0d0e12`。

两处都不是简单的「没有读取系统色」，也没有证据将问题归因于换色缓存。

## 实现边界

### 简繁快捷键

- 两个快捷键定义使用与语音、收起键相同的 `@attr/IconAlpha`，不手写透明度常量。
- 在原生 `SoftKeyView` 完成文字样式绑定后，仅对 `SimplifiedTraditionalToggleKeyView` 调用动态主题的 Header 文字适配。
- 保留原生文字颜色，只根据原生按键元数据调整 View 透明度。重复绑定从原始透明度计算，不连续相乘。
- 原始透明度通过弱引用保存。退出动态主题时恢复，普通主题未进入该路径的文字保持原样。
- 与既有功能键图标适配共用动态主题包归属判断，不扩展图标白名单。

### 快捷面板按钮背景

- 无边框时继续使用 `surface`，有边框时使用 `base`，与原生 Header 规则一致。
- `color_access_points_menu_background` 仅保留一个赋值点，主表与边框表由同一生成器处理。
- 改色修订号从 5 增至 6，使既有生成包和预览缓存按现有机制更新。

本轮不改变键位、触摸区域、简繁转换、语音、收起键、候选、学习或 Header 仲裁。

## 验证与边界

- Java 重新生成 smali，隔离包从原始 APK 完整重建成功，审计签名与 ZIP alignment 通过。正式包名及正式产物未改。
- 固定角色期望校验有无边框的按钮背景。四份真实样式表与独立 wire-format 参考逐字节一致。
- Android fixture 验证非默认原始透明度、重复绑定、原生文字颜色保持和退出动态主题后的透明度恢复，既有图标绘制与预览缓存契约也通过。
- 真机覆盖深浅色与边框组合，以及「简 → 繁 → 简」和快捷面板开关后的状态，共 7 份像素样本。文字与语音图标实心像素最大通道差为 1，按钮背景与 Header 背景相同。一个色阶的差异属于本次两条渲染路径的量化结果，不宣称逐像素一致。
- 关闭动态配色后，原有灰白主题、蓝色操作键与快捷键样式恢复。
- 简繁快捷键静态门禁和 Android 16 基线门禁通过。未重复全部输入功能、全部普通主题或低版本模拟器验收。

证据保存在本地 `work/header-color-audit/`。截图仅包含隔离合成输入场景的键盘区域，快捷面板展开时仅保存左侧按钮局部。

测试后已恢复默认输入法与系统深色模式，卸载隔离输入法和辅助包。没有更换壁纸、切换系统主题色、操作正式词典或创建手机公共存储临时文件。

客观回归已完成，主观视觉效果待用户确认。本分支尚未合并或发布。
