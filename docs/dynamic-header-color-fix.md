# Header 配色、快捷返回与引导布局修复

## 已确认问题

用户先反馈动态配色的「简/繁」文字及快捷面板按钮背景，随后在普通浅灰主题中复测，要求无边框时按钮背景与主键盘区域一致。

当前普通浅灰主题实测：主区域为 `#eceff1`、Header 为 `#e4e7e9`、按钮自身为 `#ffffff`。按钮确实带独立白色背景，不能用「对齐 Header」代替用户要求的主区域颜色。

普通主题的功能文字颜色包含 80% 透明度，图标另使用原生图标元数据的透明度。上一轮仅针对动态主题的文字适配不能直接扩大到普通主题，否则会重复相乘。

另外，快捷主题入口把未访问的父页面放进返回栈，首次引导没有消费系统栏及摄像孔安全区，完成提示也比原操作按钮矮。

## 当前实现

### 原生 Header 样式

- 简繁快捷键仍使用原生 `AutoCenteredLabelView`，字号与布局复用功能键样式，颜色绑定改为原生 `.icon` 样式。
- 绑定文字后使用同一按键元数据中的 `IconAlpha`，重复绑定直接设置该值，不连续相乘。
- 动态与普通主题共用这条路径。删除上一轮动态主题专用的文字适配与弱引用透明度状态，不改变图标白名单或其他文字。
- 无边框的按钮背景使用原生 `color_base` 变量，并完整显示这一颜色。有边框时保留原背景规则与原生 View 透明度。
- 原生箭头、背景 Drawable、触摸区域、快捷键动作、简繁转换、语音与候选行为保持原路径。
- 改色修订号增至 7，使动态生成包和预览按现有机制更新。

原生样式表补丁由 `scripts/theme_header_styles.py` 应用到原始 APK。组包阶段使用已打补丁的 legacy APK 作为资产来源，解决解码树已修改、成品却重新复制原始 assets 的遗漏。现代资源与 DEX 合并方式保持不变，原资源 ID 继续由既有构建链验证。

### 快捷主题入口

快捷入口以 `ThemeCatalog` 自身作为返回栈根，不补入虚拟父级。系统返回关闭宿主，页内返回按钮在栈根也关闭宿主。正常设置入口仍保存实际经过的首页、键盘和外观页面，子页面先返回其真实父页面。

### 首次引导

滚动内容消费 `WindowInsets.safeDrawing`，不硬编码顶部或底部高度。完成提示保留 Material 3 的最小交互组件高度，避免在当前字号下替换按钮时缩短步骤卡。继续由系统选择输入法，首次引导完成及退出逻辑不变。

## 验证及边界

- Java 重新生成 smali，从原始 APK 完整构建非 Debug 隔离回归包。修正资产来源后仅重新组包，成品样式表与补丁解码树相同。
- Compose 设置单测通过，快捷入口不再含父页，正常入口仍返回外观页。设置运行时、简繁快捷键、Android 16 静态门禁通过。
- 原生菜单规则的固定 wire-format 期望通过，四份动态样式表与独立参考逐字节一致。
- 真机浅灰及深灰无边框主题中，按钮背景分别为 `#eceff1` 与 `#263238`，均与主区域一致。文字与语音图标实心像素最大通道差为 1。
- 有边框切换走过真实主题操作入口，原生背景规则与透明度分支保留。没有将无边框颜色断言用于有边框。
- 从键盘快捷面板打开主题、应用主题后，一次系统返回回到合成编辑器。
- 从系统输入法选择器返回同一引导页后，Logo、标题及两张步骤卡标题的像素位置与选择前相同。测试覆盖当前设备与当前字号，不宣称所有字号或动画帧均已实测。
- 未重复全部普通主题、图片主题、低版本设备、TalkBack 或长期输入验收。新版 Android 模块 fixture 已更新接口，但本轮使用非 Debug 回归包，未运行该 Debug 专用 fixture，实际颜色由键盘入口像素对照确认。

证据在本地 `work/header-followup-research/`，旧动态专用实现的证据保留在 `work/header-color-audit/`，不能用旧的「退出后恢复文字透明度」断言解释当前实现。

临时回归包与编辑器已卸载，默认输入法恢复为用户正在体验的旧测试版，主题及深色模式保持。正式包和旧测试版的数据未改，没有更换壁纸或创建手机公共存储文件。当前仍待用户视觉确认，未合并、未发布，也未覆盖安装旧体验包。
