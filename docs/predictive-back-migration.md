# 预测性返回迁移

## 目标与阶段

用户要求从当前主线建立独立分支实现预测性返回。分支为 `feat/predictive-back`，基底为 `91366a2`，包括已验收的手写第三版和 Native 16 KiB 改动。

第一版仅接入现代设置与主题编辑 Activity 的系统预测性返回，未实现内部子页的跟手预览。用户对照其他应用后明确反馈：同一 Launcher 下其他应用的内部预览正常，测试版没有。因此不能把应用内预览缺失归因于第三方 Launcher，第一版也不能按最终页面正确就认定预览完成。

第二版补齐通用设置返回栈的手势进度转场，保留原来的访问顺序。许可正文的页内返回、主题编辑的跨 Activity 返回、首次引导及原生 IME 尚未完成专项验证，不能称为全应用完成。分支不合入主线，不发布。

## 接入依据

现代页面已使用官方 `ComponentActivity` 与 `androidx.activity:activity-compose:1.13.0`。第二版在有内部返回栈时启用 `PredictiveBackHandler`，根页面仍交由 Activity 的默认返回路径。主题编辑 Activity 使用默认返回取消编辑，成功保存仍走原来的结果回传。

官方支持在应用默认关闭时，单独给 Activity 设置 `android:enableOnBackInvokedCallback="true"`，见 [预测性返回接入指南](https://developer.android.com/guide/navigation/custom-back/predictive-back-gesture)。本阶段仅为 `ModernSettingsActivity` 与 `ModernThemeBuilderActivity` 启用该属性。

- 系统处理 Activity 之间或返回桌面的预览、取消及提交，不增加拦截默认返回的 callback。
- 通用设置子页用官方 `SeekableTransitionState` 与 `Transition.AnimatedContent` 呈现真实上一页。拖动进度只驱动呈现，完成收集并结束转场后才提交返回栈，取消时恢复原页，协程已取消时不在异常处理分支另起恢复动画。普通前进、顶部返回按钮与旧 API 返回继续使用同一转场和返回栈，不新增业务回调。
- 许可正文仍有独立的普通 `BackHandler`，本轮不宣称它具备手势进度预览。
- 首次引导的 `exitToHome()` 仍主动启动 Home 并移除任务，保留现有返回路径。它需要独立检查，不能以启用属性替代迁移。
- 应用默认 opt-out 保留，原生 IME、候选、手写及遗留入口继续原有分发，不改键盘返回顺序。
- 只在 Manifest 生成脚本定义接入 Activity 名单，成品门禁复用同一检查函数，避免维护第二份迁移名单。

`verify_target36.py` 保留原生 IME／遗留壳的检查，但不再把全部现代 Activity 描述为冻结返回。新策略接入现有 Compose 成品门禁。

## 本阶段验证

首次从原始 APK 完整重建后，成品 Manifest 策略检查通过，当时准备复用手写隔离身份，尚未安装。用户随后通知设备已远程连接，并授权清除手写测试版，因此重新构建为独立 `com.google.android.inputmethod.pinyin.predictivebacktest`，用审计设置入口直接测试现代页面，不复用旧包数据，也不主动启动或更改首次引导。

产物为 `work/predictive-back/GooglePinyin-2.1.5-predictive-back-test.1.apk`，版本名 `2.1.5-predictive-back-test.1`、versionCode `4520419`、min SDK 23、target SDK 36、ARM64、非 Debug，沿用审计签名。27,825,642 字节，独立身份版本的 SHA-256 为 `82d6a45ea2ab2dc523e0d3687a185db96d7b25f00e720a942a720a3238992314`。构建中的 v1/v2/v3 签名与 16 KiB ZIP alignment 检查通过。记录在本地 `work/predictive-back/`。

设备随后已通过远程 ADB 正常查询。前台为 Launcher，未锁屏，使用三按钮导航，默认输入法已为正式版。独立包的流式安装失败，推送安装又因连接重置失败，因此停止重复安装。失败推送的确切临时路径已清理。

已按用户授权通过 `pm uninstall` 清除手写第三版及其私有数据，设备本项目仅保留正式包，默认输入法仍为正式包。未启动新 Activity、切换导航模式或读取截图。返回提交、取消、系统预览、对话框和子页返回均未实测，旧 API ART 也未补测。没有启动额外 CI 或创建 Release。当时阻塞是安装传输失败，而非设备离线。

用户要求重试后，普通推送仍报连接重置。改用标准输入安装时出现 APK 解析失败，完整性检查发现设备收到的哈希正好等于原 APK 在第 718 字节的 `0x1A` 处截断、并按 Windows 文本模式转换后的哈希。该标准输入路径的失败有文本模式截断证据，不归为网络波动，也不解释普通推送的独立重置问题。

随后改用 Base64 文本传输，在设备端还原后核对完整 SHA-256 与本机产物一致，安装成功。只直接启动已导出的现代设置审计入口，未启动首次引导，未启用或选择审计输入法。

真实设置根页面完成边缘返回动作检查：拖回并取消后保留同一 Activity，提交后退出到原 Launcher。测试临时切换手势导航，结束恢复三按钮导航，默认输入法保持正式版。窗口输出未取得返回预览的进度或 Animator 状态，因此该检查只证明取消／提交的最终页面行为，不代替用户对系统预览动画的视觉验收。子页、对话框与主题编辑返回尚未实测。

两份明确使用过的安装临时 APK 均已删除，设备只保留正式包和独立返回测试包，手写测试包保持已卸载。证据为本地 `install-remote.json`、`runtime-result.json` 与 `cleanup-test.json`，均位于 `work/predictive-back/`。

## 第二版：通用设置子页预览

用户用 Pixel Text 对照，观察到其他应用的内部返回预览正常，但返回桌面没有预览。这个对照支持「测试版应用内预览缺失不是 Launcher 限制」，不能据此证明返回桌面缺失一定由 Launcher 引起。设置源码确认第一版只是普通 `BackHandler` 加提交后的 `AnimatedContent`，没有消费手势进度。

第二版为 `2.1.5-predictive-back-test.2`，versionCode `4520420`，沿用独立包名、审计签名、非 Debug、min SDK 23、target SDK 36、ARM64。从原始 APK 完整重建一次，APK 为 27,829,738 字节，SHA-256 `336d3f1d697e1430853e1d7636663b18ad19295e6dbe8245310c106693f5c52b`。包身份、v1/v2/v3 签名、16 KiB ZIP alignment 与设备安装后的完整哈希均通过，直接设置审计入口保持不变。

真实边缘手势覆盖「首页进入输入设置，再返回首页」的一轮取消和一轮提交。只比较软件内置固定标签的可访问性几何及出现数量，不读取截图或记录设置值：

- 松手前拖动到两个不同位置时，上一页的固定菜单内容已经出现，其几何随进度变化。证明进度驱动的上一页呈现，而不是仅检查最终落在哪个页面。
- 拉回并取消后，输入设置标题恢复原位置，首页菜单消失。
- 松手提交后，首页菜单与几何恢复到进入子页之前的状态。

这是一条真实子页路径的客观检查，不等于全部层级、视觉观感、右侧手势、RTL、快速重复操作或生命周期中断均已验收。系统返回桌面预览仍待定位，不因子页通过而宣称已修好。

Compose 模块 19 组、94 项单元测试通过。成品与构建中间树均通过现代设置门禁，target 36 门禁通过。成品解码暴露旧门禁对 ARGB 大小写与自定义 Smali label 的依赖，已按颜色值及实际条件分支目标校验，不依赖反编译后的 label 名称。4 项分支夹具检查拒绝条件反转和未定义目标。这些静态及单元检查不替代旧 API ART 或全部界面验收。

Base64 首次传输失败后仅重试一次，设备端完整哈希一致后覆盖独立测试包。元数据探针已卸载，两份明确使用过的临时 APK 已删除，未生成公共存储文件。测试前用户已选择手势导航，本轮保持其设置、Action Launcher 与正式默认输入法不变，未启动首次引导或修改正式包。证据在本地 `work/predictive-back/` 的 `runtime-test2.json`、`package-verification-test2.json`、`install-test2.json`、`unit-test2.log`。

## 第三版：保留中段可读性

用户确认第二版出现预览，但反馈拖到一半时两页内容都很淡。根因是把普通点击切页的交叉淡化直接交给手势寻址：旧页在 140 ms 内淡出，新页延迟 60 ms 才开始 220 ms 淡入，整段为 300 ms。把进度停在中段，就会停在旧页已消失、新页尚未完全显现的状态。这是本项目的动画选择问题，不是预测性返回或 Launcher 的限制。

第三版只替换预测性返回呈现，普通点击切页保留原有滑动与淡化。手势及收尾期间两页不做透明度动画：当前页在线性进度下滑出，上一页在后方做短距离位移，当前页保持上层，取消时恢复上层。用一个「空闲／手势／收尾」状态区分进度收集与转场完成，避免取消手势协程后过早恢复普通淡化效果。返回栈与业务回调保持第二版实现。

新门禁锁定预测性分支的滑动及层级，拒绝把淡入淡出重新放入该分支。对应回归用例以用户实际报告的中段可读性问题为依据，不约束普通点击动画。

独立 `2.1.5-predictive-back-test.3`（`4520421`）从原始 APK 完整重建一次，已覆盖测试包。APK 27,829,738 字节，SHA-256 `8fc6db236fdf60c6e61f94532db4fd45b5c3e4bca8d70f6c6559578c1cfaaf08`，身份、非 Debug、审计签名、v1/v2/v3、16 KiB ZIP alignment、安装后完整哈希及成品门禁通过。本轮不重复第二版已通过且未受影响的业务契约单元测试，增加一条动画回归用例。

真实输入设置返回首页的取消及提交复查通过。在两个松手前位置，当前页标题和上一页固定菜单同时存在于可访问性呈现树，当前标题随拖动移动，取消后输入页恢复，提交后首页恢复。源码与门禁证明预测性分支已移除透明度动画，几何证明真实进度及返回路径正常，但没有读取截图或测量屏幕像素对比度，最终清晰度与观感仍交由用户验收。

大块 Base64 传输连续两次失败后，改为一次分块文本传输，完整哈希一致才安装，未推断网络根因。辅助探针已卸载，明确的安装临时文件已清理，保留正式包及第三版独立测试包。Action Launcher、用户手势导航与正式默认输入法不变。证据为本地 `runtime-test3.json`、`install-test3.json`、`package-verification-test3.json`，其余未测边界继续保留。

## 下一步

1. 用户检查第三版通用设置子页的中段清晰度、拖动、取消与提交观感，当前保留用户自行选择的手势导航。未获验收前不合并。
2. 补多层级、对话框优先级、许可正文和生命周期专项，不从一条子页路径推导全部返回场景通过。
3. 返回桌面预览单独定位，必要的 Launcher 对照切换须先获授权，不静默修改默认桌面。
4. 主题编辑取消与结果回传单独检查，测试图片仅用明确授权的素材，不改壁纸。
5. 首次引导退出路径和 IME 原生返回链作为后续阶段，先确认回调及任务语义，不启用全应用属性绕过这些检查。
