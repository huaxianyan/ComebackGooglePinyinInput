## 问题与处理

### 生成包收尾失败可能被当作成功

位置：`SystemAutoThemeCompat.buildDynamicThemePackage()`。

基线通过 `closeQuietly(zip)` 关闭输出。ZIP 中央目录在关闭时写入，若关闭抛出 `IOException`，错误被忽略，后续仍可能替换文件并返回成功。
此外，旧的重命名回退会删除已有包后再重试，第二次失败时不再保留旧包，与方法声明的失败保留契约不一致。
这两条路径来自基线，但属于本分支生成包的必经代码。

已修改为在写入的 `try` 块中显式关闭 ZIP，关闭失败进入原有失败处理，删除临时文件并返回失败。
重命名失败时仅删除临时文件，保留已有可用包，不再先删除目标重试。
同步逻辑继续使用原有旧包保留和延后重试语义，没有新增恢复状态机。

验证边界：失败路径由源码确认，最新包已完成干净构建和运行期生成、读取。
没有实施磁盘满、权限破坏或存储故障注入，不将这些故障场景描述为实测。

### 图标模块验证只存在于临时工作目录

现有入库门禁覆盖固定颜色角色和四份样式表的独立编码比对。
图标掩码探针此前仅在 `work/`，从干净检出无法直接复用。
此前确实发生过把文本编辑页退格 ID 当作普通退格的错误，因此需要保留独立输入的模块验证，而不是只依靠角色表检查。

已将验证整理为：

- `scripts/fixtures/dynamic_color/ColorProbe.java`
- `scripts/test_dynamic_color_icons.py`

测试使用真实 Android `Bitmap`、`ImageView` 和 `Canvas`，不采用宿主 JVM 的 Android stub 模拟绘制。
键 ID 和期望像素为独立固定输入，不从生产白名单或归一化算法推导。
覆盖普通及输入中退格、候选页退格、Shift 各白名单入口、原图不变、边缘 alpha、密度、元数据 alpha、着色与缓存复用。
禁用 Shift 和关闭动态配色的外观保留是项目既定回退边界。

探针只接受 API 31 及以上、可调试的隔离审计包，恢复原动态与自动主题开关。
运行器不覆盖同名既有探针包，成功安装的本轮探针在结束时卸载。
物理设备和 API 31 模拟器上的模块验证均通过。
这是模块检查，不替代原生键盘的真实状态切换和按键行为回归。

### 无用局部变量

样式改写器读出的颜色局部变量不再被使用，已经删除。
