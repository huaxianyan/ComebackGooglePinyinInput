# 手写扩大时崩溃：定位与修复

## 现象与范围

用户报告：小窗口手写首次点击左上角的扩大按钮时崩溃，进程重启后进入全屏，随后来回切换正常。切换到其他输入法再回来后，可以再次触发。用户在 16 KiB 体验版和已有正式 Release 上都复现，因此将此问题与已验收的 16 KiB 改动分开处理。

设备崩溃日志确认，两包都在 `axs.a(F)` 调用 `View.setScaleY()` 时抛出 `IllegalArgumentException: Cannot set 'scaleY' to Float.NaN`。这不是原生 linker 或 ELF 加载错误。未安装原版作运行时对照，不声称原版运行时也必然崩溃。

## 原因

原生手写切换动画通过 `axp.c()` 延迟创建辅助键盘视图，随后立即用其 `getHeight()` 作为缩放分母。首次创建的视图可能尚未完成布局，高度为零，比例及插值计算会产生 NaN，现代 framework 拒绝把该值设置为 View 属性。

静态链路是 `akx.run()` → `aky.animateKeyboardViewSwitch()` → `axs.animateKeyboardViewSwitch()` → `axs.a(F)`。实际零高度是由源码与异常推导出的原因，本轮未插入探针逐字段记录异常瞬间的值。

## 修复契约

原生请求会先暂时固定 BODY 父容器高度，正常动画入口负责恢复 `WRAP_CONTENT`。首版补丁把尺寸检查放在恢复之前，导致回退漏掉布局恢复。第二版先完成这一步，再检查辅助视图及两个切换视图的实际高度。

尺寸尚未就绪时执行已有的内部动画收尾 Runnable，再返回 `false`，由 `aky` 的现有无动画完成路径执行外层切换回调。两者职责不同，外层回调不能替代内部布局及 Popup 清理。尺寸有效时继续原生动画，不额外提交切换。

- 保留原生一次性动画标志的消费顺序与其他状态变更。
- 高度恢复只有一个定义点，正常和回退路径共用它。尺寸检查仍位于 pivot、前后视图赋值及动画启动之前。
- 尺寸有效时保留原有缩放公式、插值、时长、监听器与回调。
- 不写死高度，不把零高度替换成虚构尺寸，不捕获并吞掉属性异常。
- 不修改手写识别、轨迹处理、候选、输入提交或触摸语义。

缺少布局尺寸时直接完成切换、不播放该段动画，是明确的退化行为。它复用既有正式完成入口，不是伪造布局或另设延迟重试状态机。

## 验证与交付

补丁由 `scripts/handwriting_animation_patches.py` 从原始 APK 应用，成品门禁为 `scripts/verify_handwriting_animation.py`。变异测试确认未修复的动画不能通过门禁，删掉高度检查或回退返回值也不能通过，并核对原插值方法逐字节不变。

真机自动回归使用独立审计包和空白合成输入框，仅记录视图类名、资源 ID、几何、进程身份及崩溃状态，不读取截图、用户输入、候选或正式私有数据。首版普通实机 12 次检查证明了无进程重启及手写区域变化，但没有检查 BODY 父容器是否缩短。用户反馈首次扩大下方键盘高度仍错误，相关高度正确性的推断作废。首版没有通过用户验收。

体验包为 `2.1.5-handwriting-test.1`，独立 ID `com.google.android.inputmethod.pinyin.handwritingtest`，versionCode `4520416`，min SDK 23、target SDK 36，非 Debug，使用审计签名。27,825,642 字节，SHA-256 `3204de63efe58f975824b841edc7a1261e1a1ea4b3e88c06217c87745c050e31`，v1/v2/v3 签名和 16 KiB ZIP alignment 通过，设备 APK 哈希一致。

首版两份辅助包与已验收的 16 KiB 体验包已卸载，正式包及数据未动。证据在 `work/handwriting-expand-fix/`。

修复提交 `0c6641e` 的隔离 Actions `38022668762` 全部通过，包含成品手写门禁、ELF／RELRO 审计及两次签名构建一致性检查，仅上传 Artifact，没有发布 Release。

## 第二版：高度恢复与动画高帧率

手写原生 Animator 现在接入已有服务持有的 `HeaderMotionCoordinator`，不是第二套 boost。唯一接入协议扩展为 Animator 与实际运动 View 数组，原有快捷菜单一起迁入这个协议。`SoftKeyboardView` 提供正式 renderer target 接口，枚举本体、直接渲染子层、只读的原生按键缓存与自身拥有的手写绘制层。结束、取消、隐藏、detach 及会话清理继续复用同一协调器。

第二版从原始 APK 完整重建。临时无内容观察包完成 10 次扩大／收回，含冷启动及切换 Gboard 再回来，进程未重启，所有扩大的 BODY 高度相同。两次实际原生动画各观测到 63 个渲染目标，开始全部为 HIGH，结束全部为 NO_PREFERENCE，33 个 UI 帧间隔样本的中位数分别为 8.337525 ms 和 8.339006 ms。其余尺寸不足的切换不播放动画。这不是面板刷新率、完整 FrameTimeline 或长期功耗验证。

无探针成品另外完成冷启动后首次扩大、收回、再次扩大、收回。该设备 BODY 高度每次为 635 → 335 → 635 px，手写区域为 619 → 1646 → 619 px，首次与后续一致。这些数字是该设备观察值，不写入生产实现。成品解码的手写、Header motion 与 target 36 门禁通过，快捷菜单开／关无进程重启，平台宿主契约测试通过。

第二版为 `2.1.5-handwriting-test.2`，versionCode `4520417`，沿用隔离 ID 与审计签名，非 Debug、min SDK 23、target SDK 36。27,825,642 字节，SHA-256 `8947e121363aedba84d026f4330624801d0c937c34ff929f8000d9117c968bdd`，v1/v2/v3、16 KiB ZIP alignment 及设备安装哈希通过。成品 DEX 不含临时 `MotionProbe`。辅助包已卸载，手机保留并选中无探针第二版，正式包及数据未动，本轮没有设备公共存储文件。

完整旧 API ART、全布局、动画主观观感及长期功耗仍未验证。用户负责第二版视觉与完整功能验收，未获确认前不合并，不发布。
