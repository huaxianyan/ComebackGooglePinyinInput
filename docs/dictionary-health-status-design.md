# 用户词库状态按需检查设计

## 目标

在「词典」设置页的用户词典／本地备份区域显示只读状态快照，突出词库可读取性、Rime 同步情况和上次成功同步统计，文件信息按需查看。颜色圆点配合文字辅助判断，不用未经确认的计数口径或文件存在性代替完整健康验证。

这不是完整的二进制修复或离线校验工具，也不改变现有词典内容、学习权重、导入导出格式和恢复顺序。

## 启动边界

旧设置页由 `DictionarySettingsFragment` 中的 `DictionaryAutoBackupSettingsCompat.Controller.bind()` 触发检查。现代 Compose 页面由 Activity 持有状态，状态区首次缺少结果时按需请求，通过「重新检查」按钮刷新，避免滚动重新进入可见区域就重复检查：

- 应用、IME 服务和键盘启动时不扫描
- 不注册 Worker、Job、Alarm、BroadcastReceiver 或文件观察器
- 不写入新的状态缓存
- 离开页面后通过 generation token 丢弃迟到的 UI 回调
- 「重新检查」使用独立按钮，检查期间禁用，不再让整块状态区响应刷新点击。

所有文件和 native accessor 查询都在单线程 IO executor 执行，结果只在主线程更新页面状态或旧版 Preference summary。

## 展示字段（旧版实现）

以下记录旧版字段及问题背景。第二轮体验版已改用通俗摘要、颜色指示、共享 Rime 状态与可展开详情，具体实现和验收状态见 [第二轮实施记录](rime-rc2-implementation.md)。旧状态行显示：

1. 综合状态：
   - 中文和英文 native 用户词典均可读取时显示正常
   - 存在 `_unreadable` 时提示立即备份
   - 存在 `_tmp` 时提示重启后复查
   - native 查询失败时只报告部分状态无法读取，不擅自修复或清空。
2. 词条数：
   - 中文 `user_dict_3_3`
   - 英文 `user_dict_3_3_english`
   - 两者合计。
3. 主文件大小：中文和英文分别显示 B、KB 或 MB。
4. 滚动副本：分别显示 `_bak` 是否存在及其大小。
5. 恢复旁路：统计 `_tmp` 和 `_unreadable` 数量。
6. 最近落盘时间：两个主文件 `lastModified` 的较新值。

## 词条数来源

**本轮新增纠正：** 隔离中文对照已确认 `getDictionaryCount()` 返回权重之和，不是导出记录数量。下文保留先前实现及验证背景，但其「改成 count 就得到词条数」的判断已不成立。状态展示正在重新设计，详见 [第二轮实施记录](rime-rc2-implementation.md#新确认的统计问题)。

不创建临时公共备份，也不解析用户文本。检查器复用原生导出路径所使用的两个 engine factory：

- `bdt`：中文
- `agb`：英文。

通过公开的 `AbstractHmmEngineFactory.createMutableDictionaryAccessor(USER_DICTIONARY)` 获取短生命周期 accessor，词条数应读取 `getDictionaryCount()`，并在查询后立即 `close()`，不调用 `exportAllEntries()` 或分配完整词条数组。

**已修复的显示缺陷：** 旧实现误用 `getDictionarySize()`。当时 Pixel 审计词库的只读对照中，中文 size 为 533,345，count 为 97,534，英文 size 为 2，count 为 0。创建未持久化副本前后的结果一致，证明两项 API 不是同一统计值。状态页因此把 533,347 错误显示成合计词条数，当时将合计 97,534 当作词条数的判断也已被后续权重对照纠正。size 的具体内部单位未确认，不将其解释为词条数、容量上限或内置词库数量。探针只读取整数，不枚举词条，不调用 persist，结束后已卸载。

旧版 Java 与 APK 曾改用 `getDictionaryCount()`。`4520424` 隔离包在 Pixel 上通过真实状态接口验证 0、200、240 条，实际 Compose 页面也分别显示中文／英文／合计为 240／0／240 和 0／0／0。空词库结果排除了此前英文 size 为 2 却被当成 2 条词条的问题，非空结果与独立生成的样本数量一致。本轮没有修改用户保留的候选包或其词库。

查询通过反射完成，以避免新 Java helper 对混淆类名产生编译期依赖。任何反射或 native 异常都被降级为「无法读取」，不得传播到设置页主线程。

## 一致性与安全

状态采样同步在 `SaveDictionaryTask.sSaveLock` 上，与已经加固的保存和原生导出序列化：

- 避免在 `main → _bak`、`_tmp → main` 轮换中间读取
- 文件快照和 native 词条数尽量来自同一稳定窗口
- 如果无法取得该锁，返回检查暂不可用，不用自己的局部锁冒充保存锁。

`_bak` 与 main 大小不同本身不是故障：滚动副本通常代表上一次成功保存。状态页只报告其存在和大小，不把「不相同」误判为损坏。

## 词库与 Rime 同步状态总览

用户要求在现有用户词典状态区域加入 Rime 同步相关信息，并改善术语和信息层次。本项与手动同步简化、目录迁移修复一起完成了代码、工程回归和体验包安装，主观视觉及完整 TalkBack 体验仍待用户验收，详见 [第二轮实施记录](rime-rc2-implementation.md)。

### 优先显示用户关心的信息

- 本机用户词库是否可读取，中文、英文数量分别表示什么
- 本机词库最近更新情况，不将文件修改时间扩大解释为所有词条均已保存
- Rime 是否尚未配置、尚未完成首次同步、正在同步、等待重试或需要用户处理
- 最近一次成功同步的时间，失败不能覆盖成新的成功记录
- 自动同步是否开启、所选间隔或当前暂停状态
- 最近同步中仅保留在 Rime 的条目数量，详情按需查看，不要求逐项确认

信息按本机词库与 Rime 同步分组，不堆成没有层次的长字符串。本机词库可读取与同步暂时失败是不同状态，不能因为目录暂时不可访问，就把整个用户词库描述为损坏。

### 布局与操作

- 指示器和简短状态文字放在独立状态行，不使用 `ListItem.leadingContent` 让整块文本缩进。标题、说明和参数保持与其他设置行相同的左边距。
- 本机词库的状态与完整参数在 Rime 信息之前。未配置 Rime 时不展示它。折叠时仅显示已开启的自动备份、Rime 自动同步摘要，展开仍可查看已配置的手动 Rime 信息。摘要复用原有状态来源，失败优先于旧成功时间。
- 默认折叠参数，使用描边按钮「展开详情／收起详情」及独立的「重新检查」。按钮空间不足时自动换行。
- 展开和收起使用 `AnimatedVisibility` 的纵向伸缩及淡入淡出，箭头同步旋转。展开仅展示已有快照，不新增检查、词典扫描或同步操作。

该布局已在隔离包通过界面回归，核对标题与参数的左边距、默认折叠、操作按钮、本机参数先于 Rime，以及未配置时省略 Rime。正式签名 `2.0.11-rc.3`（`4520398`）已保留数据覆盖安装，默认输入法未变。正式页面已确认默认折叠和两个按钮正常显示，未发起同步或改设置。动画使用官方 Compose 实现，实际观感与完整 TalkBack 体验仍由用户验收，没有读取截图。

本轮只修改 Compose 界面和文案。隔离包复用已验收的 Native／legacy 基础产物，只重建 Compose 部分，正式包从原始 APK 完整重建并通过签名、包属性、静态门禁和资源 ID 检查。隔离包、空白测试目录及 UI dump 已清理，证据在 `work/dictionary-status-layout/`。

### 复查稳定性与折叠摘要

`2.0.11-rc.4` 进一步落实用户反馈：

- 删除下方 Rime 设置区域独立的「当前同步状态」行，保留「自动同步」下的说明。这不等于删除词库状态区的 Rime 信息。
- 复查开始时保留上次状态标签、说明及参数，只在检查按钮的等尺寸图标位显示进度。此前暂时移除说明并替换为较长加载文案会改变状态区高度，推动后续设置项移动。修复不固定整块高度，也不用动画掩盖高度变化。
- 自动备份开启时，在词库状态区显示已有的备份摘要，正常情况下为上次成功备份时间。无成功记录时明确说明，发生错误时保留错误提示。
- Rime 自动同步关闭时不显示折叠摘要，展开后仍可查看已配置的手动同步信息。开启后显示同步摘要与已有成功时间。

隔离界面回归在保存锁被暂持期间触发真实「重新检查」，核对检查前、检查中的标题、说明、按钮及后续设置位置不变。另通过隔离包的真实备份与同步入口准备成功记录，验证摘要随自动开关显示／隐藏，以及展开仍可查看手动 Rime 信息。没有新增 Native 修改、全词库扫描或后台调度。

正式签名 `2.0.11-rc.4`（`4520399`）已覆盖安装，安装身份、默认输入法及 APK 哈希已核对，未修改正式目录或自动开关，也未发起正式包同步。隔离包、探针、临时目录和 UI dump 已清理，证据在 `work/dictionary-status-summary/`。实际动画观感与完整 TalkBack 体验仍由用户验收，本次未发布。

### 颜色指示与同步时间

用户要求参考此前 SyncClipboard Kotlin 的健康状态指示方式，为词库状态加入颜色指示器。实施时核对该项目已有呈现，不凭印象复制固定色值。颜色和状态文字由同一份状态模型决定，区分正常、需注意、异常以及未配置等中性状态，同时适配明暗主题、对比度和 TalkBack，不能只靠红绿颜色传达信息。

自动同步关闭或尚未配置本身不是故障，正在处理与等待安全重试也不能一律标成词库损坏。本机词库与 Rime 同步仍分别表达各自状态。颜色只表示现有检查覆盖范围内的结果，不代表完整词库校验已经通过。

Rime 自动同步开启后的正常摘要参照自动备份显示「上次同步」的成功时间，沿用系统日期、时间格式。手动与自动同步复用同一个最近成功记录，不另建自动专属时间源，也不从已有中文摘要反向解析时间。没有成功记录时显示尚未同步，失败或仅启动任务不能更新成功时间。进行中、等待重试和需处理的问题优先清楚呈现，保留的历史成功时间不能掩盖当前异常。状态总览与自动同步区域使用同一来源，避免显示不一致。

### 文案与详情

主展示不再使用「滚动副本」「恢复旁路」「最近落盘」等难理解的术语，也不展示内部类名、阶段枚举或文件后缀。默认只显示状态摘要，详细参数与同步数量收进按需查看的详情，详情也使用普通用户能理解的说明。

异常说明发生了什么、用户现在可以做什么。可以自行重试或恢复时，只展示进展，不将程序内部工作转成用户待办。存在恢复副本不等于已验证它可用，也不等于用户选择的外部备份已经完成，不能把内部保留副本和备份／导入目录混称为同一种备份。历史异常文件存在也不能直接表述为当前词库仍然损坏。

### 数据来源与边界

Rime 状态复用现有同步设置快照、持久状态和生命周期通知，与 Rime 设置区域保持一致，不另建一套调度、错误分类或恢复状态机。状态刷新只读且按需执行，不触发同步、迁移或恢复，不为了显示数量重新遍历整个 SAF 目录或导出完整词库。Rime 成功状态只说明本次可见文件的处理结果，不声称其他设备或外部同步软件已经完成同步。

此前用户授权的英文导出中，原生统计值为 42，导出接口返回 28 条，而这 28 条的权重之和为 42。后续中文合成对照也确认统计值是权重之和，不能继续按词条数解释。优化数量展示时需核对统计口径，不把未知含义的值标为精确词条数，也不将不一致口径直接相加。不能为了得到一个展示数字，在每次刷新时采集全部词条正文。

## 明确非目标

状态页不会：

- 自动备份、自动恢复或启动扫描
- 计算或上传词条内容
- 显示具体用户词语
- 修改、压缩、清空或重新保存词典
- 将安装内状态写入公共目录
- 把文件缺失单独判定为损坏（空词库可能尚未落盘）
- 替代真实导出验证、SHA-256、root 只读审计或故障注入测试。
