# Rime 自动同步设计

> 状态：范围已确认，调度与入口方案已核对，尚未实现或开启自动同步。本功能纳入当前版本，与手动同步一起验收。

## 已确认的产品行为

- 默认关闭，由用户主动开启
- 自动执行新增、删除和复活，开启时明确告知删除行为
- 默认间隔为 24 小时，调整范围为 6 小时至 7 天，以小时为配置单位
- 不要求整点执行，实际运行时间由 Android 后台调度安排，可能延后
- 每轮只处理执行时所选目录中已有的快照
- 不检查文件是否「最新」，不检测 Syncthing 或其他设备的在线状态、同步进度
- 外部文件传播、下载、缓存和版本到达时机由相应软件负责
- 保留手动同步入口，复用现有同步目录、设备身份、基线与持久化复核
- 已确认仅保留于 Rime 的记录继续生效，不在每轮重新询问

自动同步不是新增的网络服务，也不是目录监听功能。开启授权不等于允许自动清空词典、重置基线、忽略故障或扩大原生拒绝例外集合。

## 已核对的现有能力

### 自动备份不能直接作为周期调度器

`DictionaryAutoBackupCompat.request(context, false)` 只检查是否到期，执行机会来自输入法既有保存检查。它没有 JobScheduler、Alarm 或 WorkManager。长期不使用输入法时不产生备份，是该功能明确的设计行为。

自动同步需要后台执行机会，不能通过复制备份代码或在每次显示、收起键盘时触发来替代。自动备份保持原有行为，本次不顺便重做其调度。

### 同步执行能力已经存在

`RimeSyncSettingsCompat` 集中持有 Rime 单线程队列和互斥状态，并统一转换错误。`RimeSyncCoordinator` 已实现预览、执行、恢复和保留拒绝项的流程，原生访问继续由 `SaveDictionaryTask.sSaveLock` 保护。

自动入口应纳入同一个队列和错误处理路径，在同一次受控操作中复用协调器的规划、执行和完整校验。不得模拟点击 Compose，也不得重新实现文件解析、同步规划、原生写入或发布事务。

手动预览的删除确认仍保留。自动任务只有在开关已开启、开启告知已经确认时，才具有自动执行删除的授权。

## 调度方案

采用 Android `JobScheduler` 的普通周期任务：

- 使用唯一任务 ID，重复设置或恢复调度时更新同一任务
- 间隔直接来自持久配置，默认值、上下界和单位换算只在业务层定义一次
- 使用持久任务保留重启后的调度，复用已有 `RECEIVE_BOOT_COMPLETED` 权限
- 不增加精确闹钟权限、网络状态约束、充电前提或常驻前台服务
- 不引入 WorkManager 或借用旧 APK 的第三方后台同步链路
- JobScheduler 从 API 21 开始可用，低版本不得加载 JobService 类；设置入口沿用现有 Rime 功能的可用范围
- 系统负责安排周期内的运行时机，不把界面间隔描述为准点保证

依据 [JobInfo.Builder 官方文档](https://developer.android.com/reference/android/app/job/JobInfo.Builder)，周期任务执行时间具有弹性，持久任务也不等于准点承诺。真实执行仍受系统后台限制影响。

任务启动后只做资格检查和异步派发，SAF 与词典 I/O 不进入主线程。任务完成后正常结束，不以失败重试参数制造短周期恢复循环。

## 开关与异常边界

### 开启

需要目录配置完整、授权可用、已有成功同步记录，且没有待处理事务。开启时展示确认说明，例如：

> 开启后，应用会按所选间隔同步 Google 拼音与此目录中的词条，包括新增、删除和重新添加的词条。执行时机由系统安排。

取消确认时保持关闭。确认后保存开关并安排任务，不能仅改变界面开关而丢失调度。

### 与手动操作交错

自动任务与手动同步共用现有互斥入口，避免同一 Rime 事务并行执行。遇到已有操作时不抢占、不弹出确认框，也不创建第二份事务。自动备份和导入保留独立业务队列，仅共享既有 Native 锁。

### 失败与中断

- 新的原生拒绝、持久化复核失败、目录授权丢失或快照无法读取时，显示具体处理状态并暂停自动执行
- 不自动选择「仅保留在 Rime」，不自动清除故障记录或重建基线
- 已有事务未完成时保留手动恢复入口，不在后台连续试错
- 系统停止任务时不等待主线程，也不强行中断 Native 持久化临界段
- 系统终止进程可能留下可恢复事务，不能把这种情况记为成功；后续发现待恢复状态时暂停自动执行
- 用户关闭开关后取消后续调度，已经进入事务的操作按既有安全边界结束或留下恢复记录，不承诺系统一定允许其运行至完成

只处理当前文件，不等于取消事务一致性校验。既有输入快照变化检查、Native 完整复核、Bridge 身份校验及文件发布协议继续保留，但不据文件修改时间猜测它是否为外部软件的最新版本。

## 最小实现范围

1. 在 Rime 业务层增加自动开关、间隔、暂停原因和调度协调，复用现有配置与结果边界
2. 增加单一 JobService 适配层及版本受控的 Manifest 注册，不新增同步执行器
3. 在现有 Compose Rime 区域增加自动开关、开启告知、间隔设置和暂停状态
4. 接通开启、关闭、间隔修改、应用更新及失败后的调度一致性
5. 保留手动同步和恢复行为，不要求重新选择当前目录或重建已有基线

状态页词条数误用 `getDictionarySize()` 的已知缺陷仍是发布前必修项，与自动同步分别处理，不把错误的 53 万显示当成压力测试规模。

## 验收范围

### 一条真实后台入口的端到端回归

在独立审计环境中完成开启告知和配置，由系统 JobService 入口执行生成快照的新增、删除与复活，确认事务完成、完整持久化及冷启动零变更。运行时不启动设置 Activity，也不要求先显示键盘。

若使用 `cmd jobscheduler run` 提前触发，证据应明确是系统入口强制运行，不宣称已经等满 24 小时或验证了真实周期时机。周期参数和重启后的调度保留分别核对。

### 必要的模块与边界验证

- 默认 24 小时及 6～168 小时边界，取消开启确认后仍关闭
- 同一任务的注册、更新与取消，重复配置不产生多份任务
- 手动操作占用时自动任务不并行修改词典
- 原生拒绝或复核失败后暂停，不绕过既有拒绝集合授权
- 已完成事务冷启动后可继续调度，未完成事务显示待恢复

上述失败边界分别来自已复现的原生拒绝、旧副本写入竞争和事务恢复要求，不扩充无依据的防御测试。

### 发布条件

自动同步、状态页计数修复、既有手动同步与备份／导入共存，以及用户日常输入体验统一完成验收后，再决定合并和发布。本设计文档本身不代表自动同步已经实现或通过测试。
