# 中文文案与排版规范

本项目的中文文档、软件界面文本和 GitHub Release 文案以 [《中文文案排版指北》](https://github.com/sparanoid/chinese-copywriting-guidelines) 为基础规范。新增或修改中文内容时，必须在提交前完成排版检查和人工审阅。

## 基本规则

- 中文与英文、数字之间留一个半角空格，例如「Android 16」「API 36」「共 6 项」
- 中文与行内代码之间通常留一个半角空格，例如「运行 `dotnet test` 后检查结果」
- 数字与单位之间留一个半角空格，例如「80 ms」「120 Hz」「16 KiB」；角度和百分比除外，例如「90°」「15%」
- 中文语句使用全角标点，完整英文语句和技术标识保留半角标点
- 中文省略号使用六点形式 `……`，中文破折号使用 `——`
- 不重复使用问号、感叹号等标点
- 专有名词遵循官方大小写，例如 Android、GitHub、Bitwarden 和 Inline Autofill
- 代码、命令、路径、URL、资源键、格式占位符、日志原文和必须保持字节不变的技术标识不作机械改写

## 项目采用的争议规则

本项目明确采用上游列为争议项的两条规则：

1. 中文正文中的超链接前后留一个半角空格
2. 简体中文使用直角引号 `「」`，嵌套引用使用双直角引号 `『』`

完整英文语句仍使用英文标点和英文引号，不把直角引号机械应用到英文正文。

## 行文方式

- 开门见山，先说明事实、结论或操作，再补充原因和边界
- 技术说明通常按「问题或目标 → 思路 → 操作 → 验证 → 限制」推进，但简单问题不强行套用完整结构
- 一个段落只承担一个主要推进点，复杂关系优先拆成短段落或列表
- 删除「本文将……」「综上所述」和无信息量的客套话，不在结尾重复全文或强行升华
- 界面文案保持直接、自然和克制，不把博客式口语套入设置项、错误提示或确认对话框

## 分号与句子结构

谨慎使用中文分号。只有并列部分内部已经包含逗号，且分号能明显改善层次时才保留；普通短句优先通过改写、连接词、逗号、句号、冒号或列表表达。

列表项如果只是短语或检查项，末尾不添加分号，也不机械地改成每项一个句号。完整说明应按语义组织成自然段，避免为了消除分号而把连续内容切成节奏生硬的短句。

## Release 文案

- 标题采用 `v版本号 - 主要功能` 的功能优先格式
- 正文来源统一保存在 `docs/releases/v版本号.md`
- 功能说明、兼容边界和验收数据使用一致术语，不夸大系统最终控制范围
- 已发布 Tag 和资产保持不可变，只允许在不改变构建身份的前提下修正文案元数据
- 发布前后都要检查标题、正文、版本号、Source commit、资产名称和校验值

## 检查方式

运行项目静态检查：

```bash
python scripts/verify_chinese_copywriting.py
```

本地可另外使用 AutoCorrect 检查确定性的中英文间距和标点问题：

```bash
autocorrect --lint --config .autocorrectrc README.md CHANGELOG.md docs
```

自动工具只负责发现确定性问题。分号、句子节奏、术语准确性、原文引用和界面语境仍需人工审阅。
