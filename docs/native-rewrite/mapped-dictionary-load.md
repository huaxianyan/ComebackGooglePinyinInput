# 映射文件接入完整词典加载

LoadUserDictionaryFile 将实际只读映射接入既有完整镜像解析器，定义在 `recovered/user_dictionary_file.h/.cc`：

```text
现有文件 → MapReadOnlyFile → LoadUserDictionaryImage
         → 检查完整文件已消费 → 发布候选模型
```

文件格式、CRC、元数据和六子模型仍由原有解析器处理。文件入口只负责映射、整文件边界与候选发布，失败时保留调用方原模型。

## 边界来源

原宿主持久化驱动已要求解析长度等于文件长度。该整文件检查现在集中到文件入口，驱动删除了原 ifstream、heap 复制和重复解析步骤。

这个检查是既有宿主消费者的契约，不据此推断尚未恢复的 Android accessor 初始化规则。字节区域入口仍返回消费长度，保留流中后续数据的既有语义。

既有驱动还区分输入访问失败与内容无效。映射层报告同次 fstat 发现的空文件，文件加载层将它归为无效镜像，其他映射失败保留访问失败类别。未增加第二次文件打开或统计。

实际缺失输入的 validate 仍返回 `2`，可读取的空文件仍返回 `1`。两项字面返回值校验通过，保留 Java 消费者对输入故障与加载失败的区分。

## 映射保活与保存

文件入口返回后，模型子表通过原区域切片持有映射，后续读取和编辑继续使用同一所有权与 COW。

直接 `wb` 保存会截断目标。保存到原映射文件前，流程使用既有 DuplicateUserDictionary 产生独立快照，再释放原映射模型。该复制实际执行完整编码和加载，没有新增复制算法或返回成功的替身。

宿主 persist 驱动也使用这个快照入口，避免同一路径保存时仍读取已截断映射。Java 文件替换策略继续沿用现有实现。

## 验证

延伸既有完整镜像端到端流程，未增加另一套夹具：

1. 保存实际文件，通过新映射入口加载，确认累计 `151`、关联 `2`。
2. 工厂返回后读取两个字面 payload，再通过真实编辑器删除一条关系。
3. 用原复制入口隔离保存快照，释放源映射，覆盖为较短的第二代文件。
4. 重新映射第二代，确认累计 `150`、同步值 `7`、关联 `1` 及剩余字面 payload。

增量编译后，完整镜像和实际映射流程通过。跨运行时消费者也改用映射，因此另跑既有 Windows JDK/WSL1 文件替换流程，确认备份滚动、真实失败保存、启动恢复和清理均通过。

结果分类改变共用头声明，本轮升级一次严格全 recovered/protobuf 编译，并重新链接三个消费者，通过。已通过的运行流程未因全量编译重复执行。

本轮只使用项目内合成文件。验证完成后清理两代夹具与本轮探针可执行文件，保留可复用对象和研究证据。

## 未覆盖部分

映射的 int32 长度限制、唯一关闭和未恢复钩子沿用 [只读映射源码](file-mmap-source.md)。共享映射要求调用方保持源文件稳定，持有 fd 不等于能安全读取被外部截断的文件。

未新增 accessor 锁、Android 初始化、旧文件格式、跨进程协调或磁盘提交保证。后续 [Android accessor 取证](accessor-initialization.md) 确认了原重载先清除旧句柄，不能把本入口的失败保留语义直接套到 accessor。

本页宿主验证未执行原 ARM64、操作设备或访问用户词典，沿用当时 `274` 区域证据。后续创建与发布取证另有记录。
