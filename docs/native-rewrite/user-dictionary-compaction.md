# 接通真实模型 compact

CompactUserDictionaryAtCutoff 恢复 `0x1a3758` 的模型级流程：

```text
实际键与池顺序快照
  → 模型报告计数与原 float32 限额
  → 原日期候选和比较器
  → 原堆选择、保留前缀与删除后缀
  → 逐项实体删除及官方外层累计更新
```

它组合已有实际组件，不增加第二个排序器、计数副本、临时 backend 或假 compact。两个编辑器须与同一就绪模型绑定，调用方在整个操作期间保持独占。

## 保留原完成语义

ARM64 在 `0x1a37e8` 保存迭代结束结果，`0x1a392c` 将它作为返回值。删除循环在 `0x1a39b0` 调用原实体删除，不根据其返回值中止。

因此当前实现也按原后缀顺序继续每次删除，返回 true 表示遍历完成，不表示每条删除均成功，更不表示事务或磁盘提交。没有回滚或额外错误恢复。

## 一条真实端到端流程

原完整镜像流程从实际加载的两个关联开始：

- `a → b`：权重 `150`，日期 `1`。
- `b → a`：权重 `1`，日期 `2`。
- 外层累计 `151`，内部关联数 `2`。

传入 limit `2`、cutoff `1` 后，原 float32 步骤将数量限制为 `1`，日期优先的原比较器保留较新的轻条目。实际删除较旧的重条目，再完整编码和重新加载，结果为唯一 `b → a`、原六字节 payload、外层累计 `1` 和内部关联数 `1`。

严格增量编译选择模块与新组合模块，加入现有 archive，再执行同一流程，通过。没有重新全量构建或重复已冻结的 ARM64 字节比较。

## 尚未接入的上层

AtCutoff 保留原内部 cutoff 入口。[真实日期包装](dictionary-day.md) 已用 time(NULL) 接上 `0x1a39d8` 的原生日值减 `62` 和同一模型流程，没有伪造当前时间。

JNI/accessor 锁和 Android 保存任务仍待接入。

临时快照和计划使用可读源码的数据结构，未承诺原分配次数或内存成本。OOM、全部损坏数据、反向游标、原 ARM64 执行和 Android 设备持久性尚未验收。
