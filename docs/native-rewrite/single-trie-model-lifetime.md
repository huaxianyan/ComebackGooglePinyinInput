# SingleTrie 模型持有与编辑器生命周期

已恢复当前格式 SingleTrie 的宿主模型持有、长期编辑器缓冲准备及候选发布边界。存储和现有编辑协调器由同一个拥有对象管理，成功替换才释放旧对象。它不是原工厂、虚接口句柄或 Android 运行时的替身。

## 原路径

原 `0x1a2b38` 在局部模型通过格式、规范尺寸和六字节 payload 检查后，调用模型 slot 19 获取编辑器。只有编辑器非空才发布候选数据、编辑器及 codec；获取失败返回错误。

`0x1a3c9c` 接收候选成功后，依次更新官方元数据、`+0x48` 模型、`+0x50` 编辑器和 `+0x98` codec，释放各自旧对象，最后把 `+0x10` 字节设为一。候选解析失败保留旧模型及编辑器。

SingleTrie slot 19 的 `0x1c9860` 先检查模型就绪字节，再取 trie slot 15 和 kind 为零的 slot 7 游标。两者都非空才进入 `0x1c9700`。构造函数持有实际下层对象和节点搬迁回调，并准备三块缓冲：

| 缓冲 | 原尺寸 |
| --- | --- |
| 追加记录 | metadata 中的 payload 长度加八字节有序 ID 头 |
| 第一端点值 | 六字节 |
| 第二端点值 | 六字节 |

原构造不根据三次 resize 的返回值另建失败状态。`0x1c9658` 释放三块缓冲、辅助对象、搬迁回调及下层持有对象；删除入口 `0x1c96e0` 再释放编辑器内存。

## 宿主所有权恢复

[single_trie_user_dictionary_model.h](../../research/native-rewrite/recovered/single_trie_user_dictionary_model.h) 的 SingleTrieUserDictionaryModel 直接拥有：

- 一份现有 UserDictionaryStorage，继续使用相同 protobuf、容器及映射所有权。
- 同一 SingleTrieAssociationEditor，引用前面的存储，不复制编辑实现。
- 原加载成功状态字节 edit_flags，初值一，供现有用户计数入口读取。

模型对象不可复制或移动，unique_ptr 本身可转移拥有关系。调用方保持独占，不单独移动或赋值其 storage；旧引用在成功替换或拥有对象销毁后失效。成员顺序使编辑器先于其引用的存储析构，不留悬空编辑引用。

LoadSingleTrieUserDictionaryModel 复用现有镜像校验，先构造局部存储，再在稳定地址上构造编辑器，最后发布整个拥有对象。返回字节数沿用内存镜像 consumed-size 契约，不额外建立另一套文件协议、后端探测或格式回退。

SingleTrieAssociationEditor 现在直接按原构造准备三块缓冲，后续调用继续使用这些缓冲。六字节端点值尺寸在 kSingleTrieValueSize 定义一次，初始化与编辑器共用；它与同为六字节的 V21 payload 是不同协议字段。

业务操作仍直接调用原有新增、删除、学习与 compact 函数，传该拥有对象中的实际 storage、editor 及 edit_flags。不提供逐方法转发类或重复的就绪计数。

## 验证

延伸原 SingleTrie 同一实际流程：

1. 从真实原始文件映射建立拥有模型，实际编辑器缓冲为字面 `14 / 6 / 6`，成功状态字节为一。
2. 用拥有模型中的编辑器改写实际关系，再以字面外层累计五开始连续学习，得到累计七和前缀 `07 00 00 80`。
3. 只含十六字节合法头、缺少正文的候选加载失败，旧拥有指针、累计和可读取 payload 保持。
4. 用另一真实已保存镜像成功替换，得到关联数 197、累计 300。释放输入映射句柄后，同一新编辑器仍能新增实际关系，关联数到 198、累计到 303，并写入第七个独立文件。
5. 拥有模型销毁后，先前保留的实际存储副本仍能读取累计七和原 payload。新文件重新映射并获取自己的编辑器后，累计 303、同步时间 42 和新关系 payload 保持。

全源码严格编译一次，SingleTrie 完整扩展流程通过。未重跑行为不变的六子模型流程。七份本轮文件、对象、archive 和二进制精确清理，生成源码与日志留存于 `work/native-rewrite/single-model-build/`。

上述 native 路径已有中央登记及发布对照，本轮直接复用，中央仍为 `337` 区域，不重复导出或比较字节。

## 尚未恢复的边界

这是所有权重建，不复刻原对象 ABI。原发布过程先替换旧模型再释放旧编辑器；宿主拥有对象改用成员依赖顺序安全析构，未把这两种实际析构次序称为等价。当前 C++ 版本没有原虚句柄及 codec 对象的引用计数布局。

原 slot 19 的实际下层 editor/游标对象获取、失败分支和动态工厂尚未恢复。后续已完成 [获取释放链取证与驻留回调接入](trie-editor-acquisition.md)，同一协调器现在长期持有真实搬迁修复回调，实际下层直接插入也能使用。原回调对象 ABI、引用计数及虚句柄仍未复刻，不新增 mock 子句柄。

固定缓冲 resize 仍遵循原调用方式，但全部 OOM、C++ 分配异常与原获取失败的对照尚未完成。并发锁、观察者、Android 保存任务、进程生命周期和完整 accessor 学习管线仍未接入。未执行原 ARM64，未操作设备、正式包或用户词典。

后续已恢复 [kind 零读取状态与实际读值](trie-exact-match-cursor.md)，同一编辑器长期持有 key_cursor。[写编辑器的独立游标与引用缓冲](trie-value-editor-state.md) 也已接入，下一步恢复实际获取释放、模型锁和 accessor 生命周期。
