# 用户模型计数与学习协调

已恢复原 `0x1a1894`、`0x1a1bb4`、`0x1a1d9c` 的用户模型计数入口，支持 SingleTrie 与六子模型。两种后端共用计数、类别、payload 和累计规则，使用各自已有的真实编辑器。

这里只处理调用方已经生成的键。JNI 参数转换、accessor 键生成、逐键 float32 增量缩放、额外文本路径、衰减及原运行时生命周期尚未接入，不代表完整输入法学习已经恢复。

## 三个入口

[user_dictionary_learning.h](../../research/native-rewrite/recovered/user_dictionary_learning.h) 提供：

| 入口 | 原函数 | 用途 |
| --- | --- | --- |
| UpdateExistingUserDictionaryCount | `0x1a1894` | 更新已有计数，支持累加或覆盖 |
| EnsureUserDictionaryCount | `0x1a1bb4` | 按原类别与最低计数条件补写，零计数走物理删除 |
| AddUserDictionaryCount | `0x1a1d9c` | 正增量先尝试已有更新，失败后走 Ensure |

调用方提供同一就绪且独占模型的实际编辑器。六子模型传两个方向编辑器，SingleTrie 传一个编辑器。edit_flags 显式接收原对象 `+0x10` 的原始字节，不在存储中新增就绪状态或把它缩成 bool：Add 要求低位为一，Ensure 只要求非零。

## 已有项更新

读取旧项成功后按原指令处理：

1. 旧 category 小于请求值时通常直接成功，只有旧 `0`、请求 `1` 的组合继续。
2. accumulate 有效且请求为 `2` 或旧类别不为 `2` 时，以无符号 32 位执行加法，保留原 ADD 回绕。结果符号位为一时归零。
3. 请求类别为 `2` 时，结果计数只保留零或一；有效类别取请求值与旧值的有符号较小者。
4. 计数与有效类别都不变时直接成功，不刷新日期或其他 flag。
5. 真正更新时设置 flag31，保留旧 flag30，flag27 取调用参数，使用真实日值和 ExistingOnly 通道。

元数据读取按原日期输出请求检查完整六字节，旧日期不参与决策，也不留下只写不读的日值状态。类别比较仍使用原 int32 参数，不新增自定的类别准入规则。

## 保证计数与增量回退

Ensure 保留以下顺序：

- 原始状态字节为零、请求 count 为负，或 flag31 有效且 count 为零时，返回失败。
- 查找前旧计数设零、旧类别设 `2`。查找成功且旧类别更小时直接成功，此处没有已有更新的 `0 → 1` 例外。
- 请求零时调用同一用户模型物理删除入口，保留原重新读取和累计时序。
- 类别相同且旧计数不小于请求时直接成功，不因其他 flag 不同而改写。
- 真正写入时类别 `2` 使用计数一，其他类别保留请求计数；三个 flag 均取调用参数，经 CreateOrUpdate 写入。

六子模型的 Ensure slot 0 显式传空 reverse data，已有更新 slot 2 则省略该参数。恢复实现保留这个区别，不能因为零字节复制结果相同而跳过原可写值和失败路径。

Add 只接受正增量和状态字节低位有效的情况。它先调用 accumulate 为 true 的已有更新；任何 false 都进入 Ensure，包括底层写入失败。回退重新读取当前模型，不缓存第一次的旧值、不回滚已发生的底层修改，也不把成功但无写入的情况强制插入。

## 共用规则与原生差异

[user_dictionary_edit_internal.h](../../research/native-rewrite/recovered/user_dictionary_edit_internal.h) 收纳三个实际操作：后端查找加 V21 解码、真实日期编码加后端写入、成功后的累计处理。[删除与保留标记](user-dictionary-removal-policy.md) 复用同一实现，不新增后端逐方法转发壳。

新类别为 `2` 时保留外层累计。其他类别调用原 AdjustUserDictionaryTotalCount，旧类别为 `2` 时旧贡献按零处理，保留原 64 位回绕、负值归零及字段 presence。

编码器的 27 位饱和只影响落入 payload 的计数，外层累计仍使用编码前计数。例如请求 `536870912` 编码为 `134217727`，本实现按原调用顺序保留差异，不扫描或重新求和来「修正」累计。

## 实际验证

扩展原两个完整流程，所有期待值为独立字面字节和计数：

- SingleTrie 从已加载模型累计 `282`、关系 `189` 开始。为新关系增加权重 `5` 后前缀为 `05 00 00 d8`，再加三得到 `08 00 00 d0`，累计从 `287` 到 `290`。
- 同计数类别更新、低优先级请求成功且完整 payload 不变。原始状态字节 `2` 可供 Ensure 写入，但不能通过 Add 的低位门禁。
- 旧类别零、请求一的例外保留有效类别零，前缀为 `06 00 00 88`。类别二归一为一，转到类别零时只计入新贡献，前缀为 `04 00 00 c8`。
- `2147483647 + 8` 按原 32 位 ADD 变负后归零，外层扣除旧八。大计数经 codec 饱和为 `ff ff ff d7`，累计仍按编码前值变化。
- Ensure 零计数实际移除关系。最终累计 `536871198`、当前关系 `190`、固定表 `199`，保留映射模型的原标记和累计不变。
- 保存到第五个独立路径并加载，学习 payload 全六字节、外层累计、同步时间 `42` 和关联数往返成功。
- 六子模型同一入口分别走已有更新和缺项补写，得到 `03 00 00 88` 与 `02 00 00 c0`，外层累计 `14`、当前关系 `2`。

跨用户模型和两种后端，全源码严格构建一次。初次因未使用的 SingleTrie tuple 触发 `-Werror`，修正后只续编缺失对象，两个实际流程通过。补齐显式空 suffix 后，仅编译受影响的两个对象并运行六子模型流程，通过，SingleTrie 分支不变，不重复执行。

最终日志为 `work/native-rewrite/user-learning-build/resume.log` 与 `final-dual.log`。五份 SingleTrie 文件、原六子模型文件、对象、archive 和二进制精确清理，生成 protobuf 源码与日志保留。

## 证据与边界

上述三个区间与查找、codec、日值及累计均已有中央登记，本轮直接使用既有 ARM64 反汇编和原有发布对照，不重复导出或字节比较，中央仍为 `329` 区域。虚调用和 flag 参数以寄存器传递为准，不以不完整的 C 反编译参数代替。

未执行原 ARM64，未操作设备、正式包或用户词典。固定数组 codec 不复现原缓冲全部 OOM，底层部分失败、动态工厂、锁、生命周期及性能仍未完整验收。下一步恢复 SingleTrie 用户模型 compact，再连接原运行时和 accessor 学习管线。
