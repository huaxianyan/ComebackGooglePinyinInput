# Google 拼音输入法 2.0.4

本版本重点修复 Inline Autofill 建议数量上限过低的问题。此前输入法最多请求 3 项建议，而 Bitwarden 会为 Vault 入口保留其中 1 项，因此即使网站存在更多匹配记录，Header 中也只能出现 2 个凭据和 1 个 Vault 入口。

## 主要修复

- **最多显示 5 个匹配凭据**：Inline Autofill 建议总上限由 3 项提高到 6 项。以 Bitwarden 为例，现在最多可提供 5 个凭据建议和 1 个 Vault 入口。
- **保留 Provider 原始顺序**：新增建议继续按 Autofill Provider 返回顺序排列，可通过 Header 左右 rails 逐项浏览。
- **正常认证与填充**：点击仍完全交给 Android Framework 和 Autofill Provider，输入法不读取凭据正文、不转换为 Candidate，也不调用 `commitText()`。
- **避免不必要的规格膨胀**：继续使用 3 个 presentation spec。Android 会对后续建议复用最后一个 spec，因此无需复制 6 套相同规格。
- **原有安全边界不变**：单项可见 carousel、Clipboard 优先级、远端 Surface 裁剪、过期 editor/Header/generation 回调拒绝和无障碍隔离均保持不变。

## 验收

Pixel 10 Pro / Android 16 上使用 Bitwarden `2026.7.0` 和具有 7 条匹配记录的网站完成验收：

```text
5 个凭据建议 + 1 个 Vault 入口
```

逐项浏览正常，随机选择其中一个凭据后由 Bitwarden 正常完成填充。

完整构建继续通过：

- 从原始 APK 开始的可复现补丁与 Compose Material 3 Host 重建
- 6,633 个旧公开资源 ID 保持
- API 31、33、34、35、36 静态门禁
- legacy primary DEX 与 Compose/AndroidX 隔离
- APK v1/v2/v3 签名与 16 KiB ZIP alignment

## 兼容边界

- Inline Autofill 需要 Android 11/API 30 及以上，并取决于 App、Android Autofill Framework 和用户选择的 Autofill Provider。
- 实际建议数量由 Provider 决定，6 是输入法接受的总上限，不保证每个 Provider 都返回 6 项。
- TalkBack touch exploration 下的 Inline Suggestions 尚未声明支持，系统继续使用自身回退路径。
- APK 仅提供 `arm64-v8a` 架构。
