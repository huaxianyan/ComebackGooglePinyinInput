# Google 拼音输入法 2.0.7

本版本集中改进 Emoji、颜文字和符号分页体验，让 Inline Autofill 建议遵循 Google 拼音的按键反馈设置，并提高首次引导中禁用按钮的辨识度。所有改动继续保持原生输入、候选、学习、词典、手写、主题、Clipboard、Autofill Provider 和触摸语义边界。

## 主要更新

- **符号分页高刷新率**：Android 16/API 36 及以上只在 Emoji、颜文字和标点/符号分页确认 dragging 及原生 Scroller settle 期间请求系统高刷新率类别，结束、中断、隐藏或 detach 后立即恢复 `NO_PREFERENCE`。Pixel 10 Pro 上三类页面的活动帧间隔中位数由约 16.67 ms 降至约 8.34 ms，空闲后回到系统默认调度。
- **短滑翻页不再容易回弹**：仅为 `PageableRecentSubCategorySoftKeyListHolderView` 将非 fling settle 改为相对当前选中页的对称 12.5% 阈值，保留系统最小 fling 速度和其他分页控件的原生 50% 行为。真机 A/B 达到快速短滑回弹 0/20、普通点击误翻页 0/10、轻拖误翻页 0/10。
- **Inline Autofill 按键反馈一致**：Framework 完成远端建议点击后，通过 `InlineContentView.OnClickListener` 调用 Google 拼音原生反馈控制器。远端建议和本地上一项/下一项按钮均遵循按键音开关、按键音量、按键振动开关和振动时长。
- **首次引导禁用态更清楚**：第一项尚未完成时，后续按钮使用透明容器、1 dp outline 和较弱文字色，不再与步骤卡片背景融合。浅色和深色模式均已完成视觉验收。

## 安全与行为边界

Inline Autofill 的认证和填充继续由 Android Framework 与用户选择的 Autofill Provider 完成。输入法不读取 Dataset、凭据正文或 `AutofillValue`，不把远端建议转换为 Candidate，不调用 `commitText()` 或 `performClick()`，也不拦截、合成或转发远端触摸。

首次引导只调整禁用状态的视觉呈现，不改变以下行为：

- 第二项在第一项完成前不可操作
- 两项完成后才允许点击「完成」
- 完成状态继续原子记录
- 完成后打开设置并正常结束引导
- 未完成时的 Back 继续走既有退出路径。

## 构建与兼容范围

完整构建继续通过：

- 从固定原始 APK 开始的可复现补丁与 Compose Material 3 Host 重建
- 6,633 个旧公开资源 ID 保持
- API 31、33、34、35、36 静态门禁
- API 17–29 不解析 API 30 Inline Autofill 类
- API 17–35 不解析 API 36 帧率方法
- Header Platform、Inline Autofill、敏感 Clipboard 和简繁切换门禁
- Candidate 与符号分页帧率门禁
- 符号分页 settle 门禁
- APK v1/v2/v3 签名与 16 KiB ZIP alignment
- 正式 APK 非 Debuggable

兼容边界：

- 分页动态高刷提示仅在 Android 16/API 36 及以上生效，系统仍可根据屏幕能力、温度、功耗和厂商策略降低或拒绝请求。
- API 17–29 的旧 ART 运行时仍受当前 ARM64 ABI 和模拟环境限制，保持静态隔离结论，不描述为真机运行时验收。
- TalkBack Inline Suggestions 独立验收尚未完成，因此继续不声明 `supportsInlineSuggestionsWithTouchExploration`。
- APK 仅提供 `arm64-v8a` 架构。
