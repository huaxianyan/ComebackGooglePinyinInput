# Google 拼音输入法 2.0.8

本版本修复电话类型输入框首次加载 `DialKeyboard` 时可能导致整个输入法进程退出的问题，并纳入 `v2.0.7` 发布后的中文文案复审。修复继续保留电话键盘原有按键、状态处理、无障碍说明，以及统一 Header 中的 Candidate、Clipboard 和 Inline Autofill 能力。

## 主要更新

- **修复电话键盘类链接崩溃**：`DialKeyboard` 在统一 Header 改造中改为继承 `PrimeKeyboard`，但两个类原本都将同签名的 `a(JJ)V` 声明为 `final`。APK 可以正常构建，ART 却会在首次加载电话键盘类时抛出 `LinkageError`。本版本解除父类方法的 `final` 限制，使现有子类覆盖关系合法。
- **保持完整状态调用链**：`DialKeyboard` 仍保留自己的电话键盘状态回调。运行时继续先执行 `Keyboard` 的委托通知，再执行 `PrimeKeyboard` 的 Candidate 控制器更新，最后处理电话键盘专用状态和无障碍说明。
- **补充回归门禁**：统一 Header 验证器现在同时检查父类方法可覆盖、`DialKeyboard` 的父类和构造器，以及电话键盘状态回调是否保留，防止 APK 构建成功但 ART 运行时拒绝类加载的问题再次出现。
- **完成中文文案复审**：修正文档、历史 Changelog、版本化 Release Notes 和软件界面文本中的行内代码间距、中文省略号、普通分号、箭头及部分不自然的斜线并列。加载状态统一使用六点省略号，功能状态和界面语义不变。

## 问题影响范围

该问题只在系统或 App 将输入目标路由到电话键盘时触发。普通文本键盘以及未加载 `DialKeyboard` 的数字、密码和日期时间键盘不会触发同一个类链接错误。

崩溃发生在 ART 首次加载类时，而不是 apktool 或 Compose Host 构建阶段。因此，单纯确认 APK 可以组装不足以发现该问题。本版本同时保留静态类层级检查和实际设备回归，覆盖构建期与运行时两条验证路径。

## 构建与兼容范围

完整构建继续通过：

- 从固定原始 APK 开始的可复现补丁与 Compose Material 3 Host 重建
- 6,633 个旧公开资源 ID 保持
- API 31、33、34、35、36 静态门禁
- API 17–29 不解析 API 30 Inline Autofill 类
- API 17–35 不解析 API 36 帧率方法
- Header Platform、Inline Autofill、敏感 Clipboard 和简繁切换门禁
- Candidate 与符号分页帧率门禁
- 符号分页 settle 门禁
- Compose 状态与业务契约测试
- APK v1/v2/v3 签名与 16 KiB ZIP alignment
- 正式 APK 非 Debuggable

兼容边界：

- API 17–29 的旧 ART 运行时仍受当前 ARM64 ABI 和模拟环境限制，继续保持静态隔离结论，不描述为真机运行时验收。
- TalkBack Inline Suggestions 独立验收尚未完成，因此继续不声明 `supportsInlineSuggestionsWithTouchExploration`。
- APK 仅提供 `arm64-v8a` 架构。
