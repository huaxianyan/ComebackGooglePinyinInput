# 动态配色：偏淡与操作键固定绿色修复

## 目标与状态

解决用户反馈的整体配色偏淡、操作键没有随系统主题色变化的问题。
参考 Material 颜色角色，不以逐像素复刻 Gboard 为目标。

本轮实现位于独立分支 `fix/dynamic-color-roles`，父提交为 `master` 的 `931bc17`。
没有移入 Compose 开发分支的主题选择器、缓存或 minSdk 改动。
当前工作仍在验证中，尚未合并、提交或发布。

## 已定位的代码问题

正式基线只改写 Material 主表，边框表原样复制。
原始边框表有独立的操作键颜色，开启边框后可覆盖主表的系统色。
这是可导致固定绿色的一条明确路径，不代表所有反馈设备都走了这条路径。

此外，原生成包的元数据没有格式版本。
原生加载器对 `files:` 包与内置资产采用不同的版本处理路径。
修复为生成包声明当前格式，避免让当前选择器进入旧格式转换。
该路径仍需结合实际键盘渲染确认，不能只凭生成文件宣称用户问题已解决。

配色偏淡的来源分为两层：颜色角色的层次不足，以及原始功能图标掩码自身的透明度。
它们分别修复，不通过全局取消透明度或修改原始图片来处理。

## 实现

### 一套角色，两份样式表

系统颜色角色集中定义一次，再映射为原生样式变量。
主表和边框表从同一份角色生成，操作键的底色与前景保持成对。

| 对象 | 角色或处理 |
| --- | --- |
| 键盘底 | `surfaceContainer` |
| 字母键面 | 浅色 `surfaceContainerLowest`，深色 `surfaceBright` |
| 普通功能键与操作键面 | `secondaryContainer` |
| 操作键前景 | `onSecondaryContainer` |
| 无边框功能键前景 | `onSurface` |
| 有边框功能键前景 | `onSecondaryContainer` |
| 功能键与操作键按下态 | 前景以 `10%` 叠加到底色 |
| 浅色字母键按下态 | `surfaceContainerHighest` |
| 深色字母键按下态 | 前景以 `10%` 叠加到字母键面 |

本项目为按下态选定整数通道合成契约，不宣称等同于 Gboard 的内部舍入实现。

语义资源缺失时，使用 Android 12 提供的系统 tonal palette 作为同角色的近似回退。
如果完整角色仍无法取得，则交回原有主题，不生成夹杂模板绿色的半套配色。
该回退目前未完成低版本设备运行期验证。

生成包同时写入主表、边框表和格式版本，并把改色修订号纳入缓存签名。
样式变量编码只有一个实现点，新增边框前景变量可以覆盖主表定义。

### 功能图标掩码

图标绑定扩展接在原生 `SoftKeyView` 的 `ImageView.setAlpha()` 之后。
只处理动态生成主题中的普通 Shift、激活或锁定 Shift，以及正常退格。
禁用键和其他图标不在接入范围内。

对于主体 alpha 恰为原始掩码值 `153` 的位图，创建保留抗锯齿边缘的满幅掩码。
原位图、元数据 alpha、Drawable alpha 和色彩过滤器均保留。
标准不透明图标保持原样，结果以弱引用源位图为键缓存。

关闭动态配色，或实际主题已回退到其他槽位时，图标扩展立即交回原实现。
该扩展已生成 smali，并在隔离成品中通过 ART 加载和普通键盘的 Shift、退格像素检查。
普通键盘实际使用 `softkey_del` 和 `softkey_del_composing`，不是文本编辑页的 `softkey_delete`。
已修正图标白名单中的退格入口，候选页退格及全部 Shift 状态仍待实际回归。

### 成品续接与像素检查

设备重新连接后，复用首次完整构建后的正常解码树，更新图标绑定和生成 smali 后重封隔离包。
没有复用此前失败的 AGP 规范化资源树，也不把这次重封记作第二次从原始 APK 开始的干净全量构建。
图标掩码探针通过，修正退格入口后的成品也已实际加载和显示键盘。

一套系统色下已采集深浅色与边框开关组合。
修正退格入口后，另行采集深浅色有边框样本。
深色有边框键盘的功能键底色为 `#3a3b41`，Shift 和退格主体前景均为 `#bfbfc5`，与生成表对应。
修正前普通退格主体仍为 `#8a8a90`，不能把当时的模块探针通过当作真实退格入口已接通。

最初用户选择颜色后没有点击「应用」，主表、边框表、键盘和取色探针因此均未变化。
用户随后确认这个前提，先前「应用读到的色板未变」不再是待定位的换色故障。

新配色应用后，先捕获真实键盘，再运行配置或取色探针。
用户选择的黄红配色已显示为暖黄键盘底和桃色操作键。
经授权切换为蓝绿配色后，首次弹出键盘即显示浅蓝键盘底和薄荷绿操作键。
两套配色各覆盖深浅色与边框开关，共 8 组，操作键面和退格前景的探针、生成表与像素全部对应。

| 配色 | 浅色操作键面 | 深色操作键面 |
| --- | --- | --- |
| 黄红 | `#ffdbca` | `#612d09` |
| 蓝绿 | `#a5f2d3` | `#004432` |

无边框操作键采用圆形键面，采样限定在圆内。
最初使用外围矩形取众数得到键盘底色，属于采样区域错误，不是渲染失败。
修正采样区域后 8 组均匹配，已通过的有边框样本未重复执行。

恢复用户原有黄红配色时，隔离输入法进程 PID 保持不变，首次弹出键盘也恢复对应颜色。
这证明本次实测换色不依赖手动重启输入法。
关闭动态配色后，键盘回到原有灰白主题及蓝色操作键，再开启后恢复黄红配色。
关闭状态的全部输入功能和完整 Shift 状态仍待回归，不将这张外观样本扩大为功能无损验收。

本轮已恢复测试前的系统配色、深浅色状态和用户选用的开发版输入法，壁纸未更改。

## 剩余项目规划

以下保留已批准的执行顺序。审查、必要修复、干净构建、适用场景回归及清理均已完成，未验证边界以审查报告为准。
本分支不再增加配色功能，按以下顺序审查和收尾。
已有的两套配色、深浅色及边框组合结果直接沿用，只有受后续修复影响的场景才补回归。

### 1. 最终差异的只读代码审查

范围为 `fix/dynamic-color-roles` 相对父提交 `931bc17` 的最终改动：

- `SystemAutoThemeCompat.java`：角色定义、资源获取与回退、包生成、缓存与刷新、图标处理边界。
- `apply_patches.py`：原生绑定入口、补丁可复现性与重复应用行为。
- `test_dynamic_color_rewrite.py`：期望值独立性、真实入口覆盖及删除旧检查的依据。
- 生成的 `SystemAutoThemeCompat.smali`：与 Java 源码一致性、API 边界和绑定签名，不把生成代码的行数当作手写逻辑规模。
- 本修复文档与交接记录：已确认、推断和未验证边界是否准确。

必要时读取原始样式表、元数据和调用方核对契约，不扩展为其他功能或整个仓库的审查。
重点识别重复定义、不必要转发、无调用代码、只写不读状态、试验残留和未声明的降级。

预计 20～30 分钟。交付具体问题、位置、影响、证据及阻塞与否。
没有发现缺陷也是有效结论，不为形式上的整洁重写已验收代码。
本阶段只读，不执行全量构建，不改源码或设备。

### 2. 处理审查发现的必要缺陷

先给出审查结论，再按实际发现申报修复规模和耗时。
只修影响正确性、既定边界、可复现性或明显维护负担的问题。
低风险局部修复按明确范围执行，结构性扩大或改变既有行为时先确认。
没有缺陷则跳过此阶段，不安排预防性重构或额外测试。

### 3. 最新源码的干净全量重建

修复收敛后，使用正式构建入口从原始 APK 完整重建一次。
执行受改动影响的静态门禁、源码与生成 smali 一致性、样式改写比对及成品身份和签名检查。
使用隔离包名，不覆盖正式包。不重复未受影响且已有充分证据的检查。
预计 15～30 分钟，具体执行预算以审查后的实际命令为准。

### 4. 补齐客观回归

- 真机：Shift 激活、锁定、禁用状态，输入中退格、候选页退格及操作键按下态。
- 真机：关闭动态配色后相关按键保留原有行为，不扩大为整套输入法功能重测。
- 模拟器：选一档实际缺少语义色资源、具备 tonal palette 的低版本，优先 Android 12/API 31，验证真实回退路径的角色生成和键盘显示。

当前设备上的颜色更新和普通退格像素结果已通过，直接沿用。
本阶段预计 20～40 分钟，模拟器可用性不足时先报告环境缺口，不默认安装或写入项目外目录。
若修复涉及其他既定兼容边界，再明确增加对应验证，不机械重跑所有版本。

### 5. 收尾与交付

更新审查结果、已验证范围和仍需后续观察的边界。
恢复当轮设备状态，卸载本轮隔离包和探针，清理明确由本轮生成的临时文件。
保留必要证据，不删除其他模型的未提交改动或用户使用的其他开发包。
预计 5～10 分钟。

交付客观验收结论后，再按用户授权提交、合并和清理分支。
当前不提交、不合并、不创建标签或 Release，发布另行确认。
