## Android 17 / API 37 适配前调查

用户告知设备已于当日上午升级到 Android 17，计划的「等待 target 36 与 Android 17 真机环境」前置条件解除，要求开始适配前调查。本轮只调查，不提升 target，不改动代码。

调查文档为 [Android 17 / API 37 适配前调查](../android-17-api-37-investigation.md)，[target SDK 分阶段现代化计划](../target-sdk-modernization-plan.md) 的 target 37 小节与里程碑清单已同步更新。

### 已完成

官方行为变更已按「仅影响 target 37 应用」与「影响所有应用」两类归集并逐条判定。静态审计在本次生成的原始 APK 干净解码树 `work/a17-audit/decoded/`（3264 个 smali）上完成。

唯一明确需要改动的是 `System.load()` 的 DCL-C 只读要求。原生库加载器（混淆名 `amd`）是三级回退链：`loadLibrary` 失败后尝试加载 `filesDir/temp_lib_<versionCode>/lib<name>.so`，再失败则从 `sourceDir` 解压 `.so` 到该目录再 `System.load()`。第三步写出的文件属主可写，target 37 下会抛 `UnsatisfiedLinkError`。正常路径下 `loadLibrary` 即成功（本项目刻意用 `useLegacyPackaging = true`），所以这是潜在风险。调用方 10 处，覆盖拼音、英文、HMM 手写与手势、delight4。

判定为不涉及或低风险的项及理由均写在调查文档，其中 static final 反射限制、`MessageQueue` 无锁实现、LAN 权限、ContactsProvider CP2 两项、大屏方向限制、隐式 URI 授权等均通过静态审计排除。CJKV IME 无障碍 API 属新增能力，按项目约定需独立分支与「默认关闭」例外流程，本轮只登记。

### API 37 真机基线

设备临时直连本机后，用本机默认 ADB Server 做了只读采集，没有改动设备任何状态。设备为 Pixel 10 Pro，默认输入法已是正式包 `2.1.6`。

关键值：`ro.build.version.sdk=37`、`release=17`、`sdk_full=37.1`、`ro.build.id=CP3A.260905.009`、安全补丁 2026-09-05；内核为 `-4k`，`getconf PAGESIZE` 返回 4096，仍是 4 KiB；显示 1080×2410、density 420；导航为三键；正式包 versionCode 4520423、minSdk 23、targetSdk 36；PSS 约 88 MB、RSS 约 241 MB。

健康状态：`ApplicationExitInfo` 最近一条是当日 00:41:24 的 `PACKAGE UPDATED`，升级后没有新的异常退出。更早的三条 `APP CRASH` 在 Android 16 上、包为 `2.1.5`，堆栈是已知的手写 `scaleY=NaN`（`axs.a`），已由 2.1.6 修复，不是 Android 17 回归。DropBox 中本包条目同属 `2.1.5` 时代。当前 crash buffer 与运行日志没有 `VerifyError`、隐藏 API 拒绝或 `UnsatisfiedLinkError`。

采集时留下的两点疑问随后查清：

- **次版本号错位**：设备 `sdk_full=37.1`、本机平台 `android-37.2`，来自不同构建分支。结论是只有编译侧能写次版本号：`apktool.yml` 的 `targetSdkVersion` 写 `37`，Compose 宿主写 `compileSdk = 37` 加 `compileSdkMinor = 2`。依据取自本地构件——平台 `attrs_manifest.xml` 的 `<uses-sdk>` 没有次版本号属性，AGP 9.3.1 的 `LibraryExtension` 有 `compileSdkMinor` 但没有 `targetSdkMinor`。
- **`ACCESS_LOCAL_NETWORK` 被授予**：本包声明了 `INTERNET` 且 target 36，平台按拆分权限模型给了隐式授权，官方文档明说升到 37 后会默认被阻止。项目不使用套接字，收回该权限无功能影响，也不需要声明。

### target 37 纯提升

按用户决定从 `master` 新建 `feat/target-sdk-37`，只做纯 target 提升，不预置任何猜测性补丁。改动 7 个文件加 2 份文档：`scripts/apply_patches.py` 与 `version.properties` 写 `targetSdkVersion: 37` / `TARGET_SDK=37`；两个 Compose 模块写 `compileSdk = 37` 加 `compileSdkMinor = 2`；`scripts/verify_target36.py` 按既有「自己及以后」约定接受 36 或 37；`verify_modern_settings_runtime.py` 断言串同步为 37；CI 与构建文档同步平台和版本号。

本机完整构建成功，59 个 task、17 分 21 秒，产物 v1/v2/v3 签名与 16 KiB zipalign 均通过。`compileSdk = 37` 加 `compileSdkMinor = 2` 确实解析到了 `platforms/android-37.2`。

AGP 9.3.1 会警告「tested up to compile SDK version 37.1」。本机只有 `android-37.2`，没有 `android-37` 可退，而设备 `sdk_full` 恰好是 37.1，这条警告无法靠选平台规避。以 `android.suppressUnsupportedCompileSdk=37.2` 知情接受，理由写进 `gradle.properties` 注释；重新配置确认警告消失。压制不影响产物字节，无需全量重建。

**DCL-C 实测是本轮提升的核心目的，结论是回退链不可达。**隔离包 `com.google.android.inputmethod.pinyin.target37test`（`2.1.7-target37.1`，versionCode 4520500，targetSdk 37）为全新安装，安装目录下出现 `lib/`，`legacyNativeLibraryDir` 指向它，证明 `useLegacyPackaging = true` 生效。`lib/arm64/` 权限 `drwxr-xr-x`、6 个 `.so` 全为 `-rwxr-xr-x`，均无写位，满足只读要求。`nativeloader` 的命名空间配置显示 `target_sdk_version=37`，`library_path` 为两段式（`.../lib/arm64` 在前、`.../base.apk!/lib/arm64-v8a` 在后），实际 3 条 `Load .../lib/arm64/<lib>.so ... : ok` 全部命中第一段，回退段一次未用，无 `UnsatisfiedLinkError`、无 DCL 告警。因此 2.1 节标为「潜在风险」的判断得到实测支持，无需补丁。

首次引导页也已确认：冷启动 264 ms 后直接落到 `ModernFirstRunActivity`，标题「设置 Google 拼音输入法」、两项步骤、步骤 1 按钮可用而步骤 2 因未启用而置灰、底部「完成」置灰，深色主题与三键导航均正确。启用、选择、完成三步留给用户自行走完，未代跑。

### Android 17 输入法切换器图标（新发现）

用户使用切换器时发现拼音条目前面只有一个方块剪影，而 Gboard 是可辨识的图标。放大截图确认：切换器会把子类型图标单色化并缩到约 24 dp。

- `res/xml/method.xml` 里唯一的子类型写着 `android:icon="@mipmap/app_icon"`，指向彩色键盘 PNG（144×144，键盘加青绿「拼」字徽章、透明底）。单色化后只剩「宽矩形叠窄矩形」的轮廓，就是用户看到的方块。
- Gboard 的做法是给每种语言配一个单色字形：日语是「あ」，简体中文是「拼」。把简体中文临时加入 Gboard 后实测确认，两者都只是单个单色字符，缩小后依然清晰。
- Google 语音输入没有子类型图标，切换器就只显示文字、不显示图标。
- 与 target 无关：`compat`（target 36）与 `target37test`（target 37）在切换器里表现一致。

修法照 Gboard：新增 `patches/res/drawable/ic_ime_subtype_pinyin.xml`，把 Noto Sans CJK SC 的「拼」字轮廓做成 24 dp 单色矢量（黑色填充，由系统着色）；`method.xml` 的 `android:icon` 改指它；`verify_target37.py` 增加断言，禁止子类型图标再指回 `@mipmap/app_icon`。为取参考临时加入 Gboard 的简体中文已移除，Gboard 恢复原状。

`method.xml` 有四个资源限定符变体：`res/xml/`、`res/xml-v19/`、`res/xml-television-v13/`、`res/xml-television-v19/`。资源按 API 级别解析，手机上实际加载的是 `xml-v19`，只改基础版不会生效——第一版就是这么漏掉的。四个都已改，门禁用 `res/xml*/method.xml` 通配断言。

**真机复验通过。**隔离包 `2.1.7-target37.3`（versionCode 4520502）装机后长按地球键唤出切换器，`Target37 Audit` 显示「拼」字；同一张截图里未重建的 `谷歌拼音输入法`（target 36 compat 包）仍是方块剪影，构成天然的前后对比。截图存 `images/ime-switcher-subtype-icon.png`。

第一版尺寸偏大，已校准：实测「拼」墨迹 52×52 px，Gboard 的「あ」24×25 px，约 2.1 倍。420 dpi 下 24 dp 合 63 px，20/24 × 63 = 52.5 px 与实测吻合，说明偏大的是字形占视口的比例。生成器内边距由 2 改为 7，字形收进 10 单位方框；重建为 `2.1.7-target37.4`（versionCode 4520503）后复测，「あ」24×25 px、「拼」26×25 px，高度比 1.00，图标列中心同为 x = 324.5。截图已更新。
