## Android 17 / API 37 适配前调查

用户告知设备已于当日上午升级到 Android 17，计划的「等待 target 36 与 Android 17 真机环境」前置条件解除，要求开始适配前调查。本轮只调查，不提升 target，不改动代码。

调查文档为 [Android 17 / API 37 适配前调查](../android-17-api-37-investigation.md)，[target SDK 分阶段现代化计划](../target-sdk-modernization-plan.md) 的 target 37 小节与里程碑清单已同步更新。

### 已完成

官方行为变更已按「仅影响 target 37 应用」与「影响所有应用」两类归集并逐条判定。静态审计在本次生成的原始 APK 干净解码树 `work/a17-audit/decoded/`（3264 个 smali）上完成。

唯一明确需要改动的是 `System.load()` 的 DCL-C 只读要求。原生库加载器（混淆名 `amd`）是三级回退链：`loadLibrary` 失败后尝试加载 `filesDir/temp_lib_<versionCode>/lib<name>.so`，再失败则从 `sourceDir` 解压 `.so` 到该目录再 `System.load()`。第三步写出的文件属主可写，target 37 下会抛 `UnsatisfiedLinkError`。正常路径下 `loadLibrary` 即成功（本项目刻意用 `useLegacyPackaging = true`），所以这是潜在风险。调用方 10 处，覆盖拼音、英文、HMM 手写与手势、delight4。

判定为不涉及或低风险的项及理由均写在调查文档，其中 static final 反射限制、`MessageQueue` 无锁实现、LAN 权限、ContactsProvider CP2 两项、大屏方向限制、隐式 URI 授权等均通过静态审计排除。CJKV IME 无障碍 API 属新增能力，按项目约定需独立分支与「默认关闭」例外流程，本轮只登记。
