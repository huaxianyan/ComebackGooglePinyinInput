### 发现：状态位 bit 56 越界导致输入法启动即崩

以正式包名覆盖安装 2.2.0 后，打开应用报 Application Error，崩在 `aku.<clinit>`：

```text
java.lang.IllegalArgumentException: State SHOW_PERIOD_KEY, value 0x100000000000000 is not in the range.
    at aku.a(PG:20)
    at aku.<clinit>(PG:333)
```

根因：`aku.<clinit>` 反射登记静态状态位时传入的掩码是 `0xffffffffffffff`，**只覆盖 bit 0–55**，校验规则是「字段值必须是掩码子集」。bit 56 超出掩码，静态初始化失败，进程启动即崩。

初期分析的偏差：把可用位当成 bit 55–59，忽略了掩码自身只到 bit 55。`CUSTOMIZED_STATE_VALUE_MIN/MAX`（bit 56/63）只声明、无人读，不是约束。

修复：把掩码加宽一位到 `0x1ffffffffffffff`（bits 0–56）。该常量在整个 smali 里只被这一处读取，运行期分配段最高只到 bit 43，加宽后的 bit 56 不会与生成状态冲突。已改 `apply_patches.py`、`verify_comma_period_toggle.py`、`docs/comma-period-toggle-design.md`，**尚未在设备上复验**。

### 修掉的陷阱

`apply_patches.py` 的 `--version-name`/`--version-code` 默认值原本是陈旧的 `2.0.2`/`4520387`，手动构建会产出低版本包，覆盖安装报 `INSTALL_FAILED_VERSION_DOWNGRADE`。已改为从 `version.properties` 读取，手动运行不再漂移。
