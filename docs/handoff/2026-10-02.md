# 2026-10-02

## 本轮目标

定位「2.1.4 正式版动态配色失效，而隔离测试包验收通过」的原因。

背景：用户报告 2.1.4 的动态配色键盘在他的设备上不工作；维护者随后在自己的设备上
安装 2.1.4 正式版，同样失效。用户已删除 GitHub Release（远端 `v2.1.4` 标签仍在）。

## 结论

**正式包本身没有问题。缺陷在「覆盖升级」这条路径上，而验收走的是「全新安装」。**

## 根因

`SystemAutoThemeCompat.ensureInitialized()` 用**一次性布尔标志**
`compat_theme_slots_initialized` 作为唯一判据：

```java
private static synchronized void ensureInitialized(Context context) {
    SharedPreferences preferences = preferences(context);
    if (preferences.getBoolean(INITIALIZED_KEY, false)) {
        return;                                   // 一旦为真，永久跳过
    }
    ...
    .putString(DYNAMIC_BASE_KEY, baseMaterial)    // 动态槽 base
    .putString(DYNAMIC_ADDITIONAL_KEY, ...)       // 动态槽 additional
    .putBoolean(INITIALIZED_KEY, true)
    .commit();
}
```

- 该标志由 `f3b264c`（2026-08-10）引入，首见于 **v2.0.1**。
- 实测 `.workbuddy/tmp/compat-apk.apk`（2.1.2 正式包）的 `classes.dex`
  **含** `compat_theme_slots_initialized`，**不含** `compat_theme_dynamic_keyboard`。
  即：任何运行过 v2.0.1 至 v2.1.3 的设备，标志早已为 `true`，且动态槽键从未存在。
- 全仓核对：`DYNAMIC_BASE_KEY` 只有两处引用 —— `ensureInitialized` 的写入
  与 `baseKey()` 的读取。**没有任何其它写入点**，因此缺失是永久性的。

## 失效链

```text
动态槽键缺失
→ preferences.getString(key, "") 得到空串
→ writeSlot(SLOT_DYNAMIC) 把 keyboard_theme 与 additional_keyboard_theme 都写成 ""
→ 主题解析拿不到有效值，退回内置默认主题
→ 用户观感：开了「动态配色」，键盘没变
```

## 为什么测试版通过、正式版失效

| | 测试包 `…pinyin.dyndbg` | 正式包 `…pinyin.compat` |
| --- | --- | --- |
| 安装方式 | 全新安装 | 覆盖升级（2.1.3 → 2.1.4） |
| `compat_theme_slots_initialized` | 不存在，初始化跑满 | 早已为 `true`，函数直接返回 |
| 动态槽键 | 已写入 | 永远缺失 |
| 结果 | 通过 | 失效 |

**教训**：验收用的是全新安装，用户走的是升级路径。
「标志位式一次性初始化」在新增持久化键时必然漏掉老用户 ——
这是新增持久化键的通用陷阱，不限于本功能。

## 已排除：正式包构建本身没有问题

对比 `dist/dyn-host2-debug.apk`（验收通过）与
`work/release-verify-2.1.4/ComebackGooglePinyinInput-arm64-v8a-2.1.4.apk`
（SHA-256 `1b30290d…0d65b`，与发布页一致）：

| 项 | 结果 |
| --- | --- |
| `assets/theme/**` 75 个条目 | size 与 CRC **全部相同** |
| `classes.dex` | **大小完全相同**（3,334,260 字节），仅 CRC 不同 |
| legacy dex 注入内容 | 两个包**都含** `applyOnKeyboardShown`、`setDynamicEnabled`、`rewriteStyleSheetColors`、`compat_theme_dynamic_keyboard`、`files:dynamic_theme.zip`、`style_sheet_material_dark.binarypb` |
| 结构差异 | 仅签名 key（AUDIT 对 GOOGLE-P）、`android:debuggable`、dex 切分顺序、正式包多 `assets/dexopt/baseline.prof(m)`、`res/**` 的 PNG 被 AGP 重压 |

这些差异**均与动态配色无关**。因此不需要重新构建「正确的正式包」。

> 物证提示：`work/release-verify-2.1.4/` 里留着发布时下载回来做校验的那个正式包。
> 排查「正式包是否有问题」时应先找它，不要因为 Release 已删就认为没有物证。

## 门禁为什么没拦住

现有门禁全部只覆盖**静态正确性**：

- `test_dynamic_color_rewrite.py` —— 改色算法
- `:compose-runtime:testDebugUnitTest` —— Compose 状态
- `verify_modern_settings_runtime.py` —— 只断言 dex 里**存在**这些字符串

**没有一条覆盖「标志已置位 + 新键缺失」这一输入。**

## 建议的修复方向（待确认）

1. `ensureInitialized` 改为**按缺失键补齐的幂等初始化**：用
   `preferences.contains(key)` 逐键判断，只写缺失的键，
   **绝不覆盖已存在的键**（老用户的浅色／深色／固定三槽选择必须原样保留）。
   `resolveCurrentTheme()` 只在 `FIXED_*` 缺失时才调用。
   保留 `INITIALIZED_KEY` 的写入，但不再作为唯一判据。
2. **加固 `writeSlot`**：解析出的槽位值为空时不要写进 `keyboard_theme` 与
   `additional_keyboard_theme`。把这两个键写成空串会把用户当前主题**打掉**，
   比「动态配色不生效」更糟；空值应视为「槽位未初始化」并穿透回退到原有三槽逻辑。
3. 补一条**升级路径**验收：预置「标志为真、动态键缺失」的 prefs 后再装包。
4. 发布身份：`v2.1.4` 标签仍在远端，正式包已被用户安装过，
   建议升到 **2.1.5 / versionCode 4520406**，并在发布说明中写明 2.1.4 的升级路径缺陷。

## 已实施的修复

### 代码

`patches/java/com/google/android/inputmethod/pinyin/SystemAutoThemeCompat.java`：

1. **删掉一次性标志** `INITIALIZED_KEY`，`ensureInitialized` 改为逐键补齐：
   先用 `hasEverySlotKey()` 判断八个槽位键是否齐全，缺哪个补哪个，
   **已存在的键一律不覆盖**（老用户的浅色／深色／固定三槽选择必须原样保留）。
   `resolveCurrentTheme()` 只在 `FIXED_*` 缺失时才调用。
2. **`writeSlot` 加空值护栏**：槽位值为空时记一条诊断并直接返回，
   不再把 `keyboard_theme` 与 `additional_keyboard_theme` 写成空串。

smali 已用 `scripts/generate_system_auto_theme_smali.py` 重新生成，
4479 行，两次生成哈希一致（`1092c33a…631cb`）。

### 门禁

新增 `scripts/verify_theme_slot_initialization.py`，四条断言：

1. 每个槽位键都必须在 `ensureInitialized` 中被补齐。
   槽位键从 `baseKey` / `additionalKey` 读出而**不硬编码**，
   因此日后新增槽位漏改初始化必然失败。
2. `hasEverySlotKey` 必须覆盖每一个槽位键。
3. `ensureInitialized` 必须逐键判断（含 `contains`），且**不得**出现 `getBoolean(`。
4. `writeSlot` 必须在 `commit` 之前拒绝空槽位。

**双向验证**：对当前源码通过；对 `7a2166b`（2.1.4 发布时的源码）运行报出 12 条失败，
其中包含根因那条「ensureInitialized reads a boolean flag, which skips every key
added after a device was first initialized」。

已接入 `.github/workflows/build-release.yml`，紧跟 `Verify reproducible theme-slot Smali` 之后。

### 发布身份

`VERSION_NAME` 保持 `2.1.4`，`VERSION_CODE` 由 `4520405` 提到 `4520406`，
让装过首发 2.1.4 的设备能覆盖升级。远端 `v2.1.4` 标签需要强制更新到新提交。
