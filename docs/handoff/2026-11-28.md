# 2026-11-28 悬浮编辑模式收尾与胶囊取色

基线：`feat/floating-keyboard`，本轮构建 `work/floating-f-build/pill9.apk`（测试包名，未打标签）。

## 编辑模式的三个退出条件

编辑模式是悬浮专属状态，卡片被重建或键盘收起后必须退出，否则叠层会留在旧几何上。三条路径分别落在不同的钩子上：

| 触发 | 钩子 | 几何处理 |
| --- | --- | --- |
| 键盘收起 | `PinyinIME.onFinishInputView` | 位置可信，写入偏好 |
| 输入视图重建（换主题） | `GoogleInputMethodService.c()` | 位置不可信，退回上次保存的浮动位置 |
| 关闭悬浮 | `resetScale()` 与 `scheduleHandle` 的禁用分支 | 直接清空叠层、拖拽条、probe |

前两条用 `replace_once` 注入到 `scripts/apply_patches.py`；第三条原本已由 `resetScale()` 覆盖，本轮补的是 `scheduleHandle` 里发现设置已关时提前 `return` 而不清理的那处，改为调用 `dropFloatingChrome()`。

**窗口可见性不可用**：`onWindowVisibilityChanged` 在这套 IME 里不会因键盘收起而触发，曾按它实现过一次，实测无效，已删除，不要再走这条路。

**跨包调用必须 `public`**：`onKeyboardHidden()` / `onCardRebuilt()` 一度声明为包内可见，调用方在 `com.google.android.apps.inputmethod.libs.framework.core` 包，运行时直接 `IllegalAccessError` 导致输入法进程崩溃。凡是从原生包 smali 调用的入口都必须是 `public`。

## 编辑模式的重置图标

原来按钮里的「恢复默认」是 Canvas 手绘弧线，改为原生 `ic_key_reset_keyboard_material_dark_theme`（`0x7f020182`），`getDrawable` → `mutate()` → `setTint(accent)`，取不到资源时仍退回手绘。

尺寸是本轮踩过的地方：该 PNG 画布 175×175，**墨迹只占 42%**（74×63，四周有内边距）。要让墨迹等于原弧线直径（`0.84 × 按钮半径`，约 15.1 dp），绘制 bounds 必须给到**整个圆盘直径**（36 dp），`0.423 × 36 ≈ 15.2 dp`。按盘子半径的 52% 给会让墨迹只有约 7.9 dp，明显偏小。

## 胶囊取色

胶囊是悬浮卡片的拖拽条，原来固定 `0xFFC2C8D2`。目标是与「收起键盘」「简繁切换」同层的**墨色**一致。

结论与依据：

- `softkey_hide_keyboard`（`0x7f0f02b7`）、`softkey_enable_simplified_input`（`0x7f0f0276`）、`softkey_disable_simplified_input`（`0x7f0f022f`）在视图树里**解析为 null**，这一排是画布画的，`res/layout` 里也搜不到这些 id
- 同排可用的容器是 `header_area`（`0x7f0f004f`，`FrameLayout` 1080×105）；`access_points_bar` 通常是 0×0，遇到空行要继续尝试而不是直接返回
- 主键区的键是 `SoftKeyView`（删除键 `0x7f0f00b4` 为 161×155），但键的填充同样由画布绘制，按它的位置取样只会得到卡片底色
- 因此按 `header_area` 取色：把卡片画进位图，在带内 16×4 网格取样，众数当行底色，**离众数最远的颜色当墨色**，距离平方小于 `1600` 时判定没有墨色、保留默认灰

粉色主题实测：行底色 `F48FB1`、墨色 `(51,51,51)`、胶囊叠加空闲淡出后为 `(89,69,76)`。取行底色的版本因为与卡片太接近，看起来像没有胶囊。

缓存以 `area` 实例为键（`handleColorSource`），卡片重建或换主题会重新取；`removeHandle()` 会清掉缓存。
