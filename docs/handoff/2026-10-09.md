## 动态配色 Header 对照与修复

用户反馈「简/繁」文字与语音、收起键配色不同，左侧快捷面板按钮背景在部分主题下异常，并授权读取本轮隔离合成输入场景的键盘局部截图。

从主线 `99da86b` 创建 `fix/dynamic-header-color`，正式发布仍为 `v2.1.5`，没有修改正式版本身份或发布产物。

### 已确认与实现

- 「简/繁」颜色参与动态配色，实际差异来自文字与原生图标的透明度路径不同。
- 有边框时原生 Header 背景使用 `color_base`，按钮背景却仍使用 `surface`，造成色块。
- Header 文字在原生绑定完成后复用图标元数据的透明度，限定到简繁快捷键与实际动态主题包，保留原生颜色并恢复退出前的透明度。
- 按钮背景跟随有无边框的原生 Header 规则，改色修订号增至 6。
- Java 重新生成 smali，实现保存在补丁源码与生成入口，不依赖临时解码树。

### 验证

从原始 APK 完整构建隔离审计包 `2.1.5-header-audit.1`，versionCode `4520408`、min SDK 23、target SDK 36。Debug 仅限隔离身份。

四份真实样式表逐字节校验、Android 模块 fixture、简繁快捷键静态门禁与 Android 16 基线通过。
真机覆盖深浅色、边框、「简 → 繁 → 简」、面板开关和关闭动态配色后的样式恢复。
7 份像素样本中，文字与语音图标的实心颜色最大通道差为 1，按钮背景与 Header 相同。
模块同时验证非默认原始透明度及重复绑定，未改变原生文字颜色。

详细实现与验证边界见 [动态配色 Header 修复](../dynamic-header-color-fix.md)，证据在本地 `work/header-color-audit/`。

## 普通主题、快捷返回与引导布局研究

用户手动体验后反馈三处问题，要求先研究再动工，并授权相关截图采集及独立隔离包的引导复现。本阶段未修改实现源码，也未重置现有测试版的设置或引导状态。

- 当前选中颜色区第一款浅灰主题。实测主键盘背景为 `#eceff1`、Header 为 `#e4e7e9`，按钮自身背景为 `#ffffff`，与原生 Material Light 样式表一致。用户明确要求无边框时按钮背景跟随主键盘，而不是 Header，这取代上一轮仅对齐 Header 的目标。
- 普通主题的功能键文字颜色为 `0xcc37474f`，图标颜色为 `0xff37474f`，图标另使用原生透明度。因此不能简单将动态主题的 60% View 透明度适配扩展到普通主题，否则文字总透明度会成为 48%。后续应统一原生样式绑定，而不是叠加第二套改色路径。
- 快捷主题入口明确传入完整的虚拟父级路径，现有测试也要求逐级回到外观页。用户现在要求快捷入口返回直接退出，正常设置入口仍逐级返回，需同时修订导航实现与旧断言。
- 引导内容启用边到边显示，却未消费系统栏和摄像孔安全区。完成提示行也比原操作按钮矮，会改变滚动内容高度。安全区遗漏由源码确认，高度变化是否完全解释返回时的跳动尚待运行时复现，不能视为已完成验收。

证据在本地 `work/header-followup-research/`。采集空输入框时曾出现真实剪贴板预览，相关原图与缩略图已删除，未引用正文。后续应在截图保存前确认内容边界，不能依赖保存后再检查。
临时编辑器已卸载，默认输入法仍为用户正在体验的隔离测试版，系统仍为深色模式，主题未改。正式包与现有测试版继续保留。

实现前的收敛方向：复用原生主题的主区域颜色及图标样式、以实际入口页面作为返回栈根、消费引导安全区并保持完成提示的布局占位。不改变输入行为、壁纸或正式数据。
