# 首次手写扩大动画：布局就绪实验

## 保留的检查点

用户要求先保留第二版进度，再尝试首次动画。`fix/handwriting-expand-crash` 的第二版代码与记录已推送，检查点为 `dcf9ab9`，对应 `2.1.5-handwriting-test.2`。实验从该点建立独立 `experiment/handwriting-first-animation`，不改写检查点，不合主线，不发布。

## 原因与接入

原生 `KeyboardViewHolder` 已持有旧、新视图及唯一切换 Runnable `akx`，但它投递动画时，辅助手写面板还没有布局尺寸。`axp` 自己的流程稍后显示面板，首版和第二版只能安全地跳过未就绪的动画。

实验在原生动画链之前，对原本符合 `axs.shouldAnimate()`、已准备且正在扩大的请求做预检查。布局尚未就绪时，由现有服务持有的 `HeaderMotionCoordinator` 等待旧、新视图与面板完成实际布局，保留原来的 `akx` 作为恢复动作。没有第二套 Animator、插值算法或帧率请求。

- 等待布局及 PreDraw 事件，不新增固定延迟，不伪造尺寸，不强制每帧重绘。
- 等待期间保留原生暂时固定的父容器高度，避免动画开始前先跳到缩短后的高度。辅助面板暂时透明，布局完成后交回原生动画。
- 恢复、取消或放弃前先清理监听器与排队动作，恢复面板 Alpha，清空待执行状态，再执行相应动作。
- 原生取消入口、输入开始／结束、隐藏、Header 失效及 detach 共用服务协调器的清理路径。
- 无法承接请求时仍保留第二版回退。收回不进入首次扩大等待，避免扩大修复改变其既有完成语义。
- 父容器 `WRAP_CONTENT` 恢复抽为唯一原生定义点，正常动画与等待放弃共用它。

新增的 Smali 桥接只连接原生动画链、捕获的父容器及原有完成 Runnable，因为原生类位于默认包且有重名不同类型字段，不能直接用常规 Java 字段模型接入。桥接不持有输入、候选或词典内容。

## 验证

从原始 APK 完整重建后，普通实机冷启动首次扩大观测到真实原生动画，63 个渲染目标开始全部为 HIGH、结束全部为 NO_PREFERENCE，33 个 UI 间隔样本中位数为 8.337169 ms。另一次布局恢复观察得到 35 个样本，中位数 8.336590 ms。没有将这些短时 UI 回调描述为面板固定 120 Hz 或长期性能结论。

取消测试使用临时观察包，在等待建立后预置 20 ms 的诊断动作，分别调用实际切换输入法、隐藏窗口与原生取消入口。等待均被取消，重新显示输入法后没有延迟启动旧动画，进程稳定。20 ms 只属于诊断控制，不存在于生产实现。取消入口测试不等于完整快速反复点击的主观验收。第一次纯 ADB 顺序注入来不及命中等待阶段，之后改用预置动作，不把晚到的注入当作程序缺陷。

无探针成品冷启动首次扩大后，BODY 高度为 335 px，收回为 635 px，进程稳定。成品 DEX 不含 `MotionProbe`，手写、Header motion 和 target 36 成品门禁通过，宿主契约与变异测试通过。设备尺寸是观察值，不写入生产实现。

第三版为 `2.1.5-handwriting-test.3`（`4520418`），沿用隔离 ID 与审计签名，非 Debug、min SDK 23、target SDK 36。27,825,642 字节，SHA-256 `ab36efc1dd6735393f70ea8b5c11206de5c3bbfa9c2ab4e7948f64118bcd01df`。v1/v2/v3、16 KiB ZIP alignment 及设备 APK 哈希一致性通过。证据在 `work/handwriting-expand-fix/`，没有读取截图或采集内容。
